# 素の HTML のページ（`screens/page`）

このパッケージは、申請の種類の画面（申請書、承認カード、チケットの一覧、履歴）を素の HTML で見せ、そこからブラウザが送ったフォームを API の操作に読む。ringi の DESIGN 13.6 の「代わりの形」にあたる。A2UI のレンダラが無くても、どのブラウザでも申請し、承認し、申請を読める。必要なら JavaScript が無くてもよい。画面のまわりのページも作る。ホーム、各ページの上に置く帯、ページの代わりにサーバーが見せる知らせである。

パッケージ `github.com/i2y/ringi-server/screens/page` は、標準ライブラリだけを使い、パッケージ `screens` の上に作ってある。画面の値は `screens` の `Form`、`Card`、`List`、`Mine`、`History` が入れ、名前は同じ `Lookup` で引き、送られたフォームは `screens.Action` にして、`screens` の `Set.Operation` が冪等キー付きの操作にする。断りは `screens` の `screens.Refusal` で受け、その場所は `screens.ReadPlace` で読み、`screens` の文（`screens.RefusalWords`）で言う。このパッケージは、それらを作り直さない。足すのは HTML と、人が打つ値（金額、率、日付、明細、ファイル）の読み方と、文言である。文言の日本語の文は、フレームワークのほかの文と同じ決まりで名前を置く（パッケージ `internal/jatext`。これも標準ライブラリだけを使う。3.5）。

`screens` と同じく純粋な関数で、何も保管せず、だれにも尋ねず、何も配らない。チケットを読み、gate に尋ね、ファイルを預かり、操作を実行し、ページを送るのはサーバーである。サーバーのその部分を HTTP で受け持つのは、パッケージ `web` である（[../../web/DESIGN.ja.md](../../web/DESIGN.ja.md) の 9 節）。

サーバーは次のように使う。

```go
pages, err := page.New(set, page.Options{Assets: "/assets/"})

// チケットの承認カードを GET する
pg, err := pages.Card(page.Card{
	Card:   screens.Card{Language: "en", Ticket: ticket, Can: can, Names: names, Serving: screens.Serving{Find: "/a2ui/find"}},
	Action: "/tickets/T-1",
	Now:    time.Now(),
})
w.Header().Set("Content-Type", "text/html; charset=utf-8")
w.Write(pg.Document())

// それを POST する
r.ParseMultipartForm(32 << 20) // フォームにファイルが無ければ r.ParseForm()
rd, err := pages.ReadCard(in, page.Post{Values: r.PostForm, Files: files(r)}, keep) // keep：この人の物
switch {
case errors.Is(err, page.ErrPost): // ページの投稿でない：400
case err != nil:                   // 500
case rd.Stay():                    // フィールドで押した Enter：204 No Content。ブラウザはページをそのまま残す
case rd.Operation == nil:          // ページをもう一度見せる：pages.Card(in に Now: time.Now() と Again: rd)
	// rd.Refusal() が断りを言えば 409（"stale" なら、チケットを読み直して）。rd.Problems が
	// おかしい所を言えば 422。行を足したか消しただけなら 200
default:                           // rd.Operation をその人として実行する（Do：ID、チケット、本文、キー）
	// 受け付けたら、チケットの承認カードへ 303。断られたら、API が答えた screens.Refusal で
	// rd.Refused(refusal) としてもう一度見せる（stale なら、チケットを読み直してから）。
	// 本文を読めなかったら rd.Invalid(problem) としてもう一度見せる。
}
```

帯はページの `Bar` に入れ（`pg.Bar = bar`）、`Document` が画面の前に置く。知らせはページの代わりに見せる。

```go
bar, err := pages.Bar(page.Bar{Language: "ja", Home: "/pages/", Person: "営業担当 1", SignOut: "/logout"})
pg, err := pages.Notice("ja", page.NoticeNotFound, "/pages/") // サーバーが 404 で送る。リンクはホームへ
```

`in` は、ページを作ったときの入力である。投稿が来たら、サーバーはページのときと同じくチケットを読み、見る人ができること（`Can`）を尋ね直す。新しい申請の申請書は、見せるたびに（もう一度見せるときも）新しい面（`Form.Surface`。ランダムな ID。4.5）で見せる。その投稿を読むときは `in.Surface` を空にしておくと、投稿から面を取るので、サーバーは面を覚えなくてよい。チケットのページは、見せたときと同じチケットの面で読む。

## 2. 読む物

`New` は一式のすべての種類について、説明（`types/<種類>.json`。`screens` の `Set.Description` から）と、画面のボタン（`Set.Buttons`）を読む。フレームワークは、どの種類の型も知らない。どのページも、説明、チケット（契約の JSON）、見る人の `Can`、`Lookup` から同じコードで作る。種類の名前で分かれるコードは無い。

説明からは、種類の題とラベルを読み、フィールドごとに、名前、書いた名前、ラベル、型、範囲（`min`、`max`。数は送る整数で、日付は日付で）、長さか行の数の下限と上限（`count_min`、`count_max`）、選択肢、任意か、計算するか、承認者だけが入れるか、承認者が直すか（`approvers_edit`）、条件（`shown_when`、`required_when`）を読む。明細の行のフィールドも同じに読み、ステップと決め方のラベルも読む。知らないキーは読まずに置いておくので、説明にキーが増えても読める。

`New` は、正確に読めない数の型を持つ説明を断る（`ErrDescription`）。刻みを書いていない率と、単位の表に無い単位である。説明は、どの率にも刻みを書く。ソースが刻みを書かない率は、ringi の数え方のとおり `rate[step 1%]` と書く。数を間違えて見せたり読んだりするくらいなら、ページが無いほうがよい。

## 3. ページ

`Form`、`Card`、`List`、`History` は、それぞれ `screens` の同じ名前の入力と、ページに要る物を取る。ページが見せるのは、`screens` が同じ名前の A2UI の画面（自分の申請の一覧では `mine`。3.3）に入れるデータを、説明の言葉で読んだ物である。同じ値を、同じ `Lookup` の呼び出しで引いた同じ名前で、同じ置き場（`/can`、`/before`、`/edit`、`/send_back`、`/add_approver/parts`、`/route`、`/tickets`、`/history`、`/find`）から見せる。`screens` が埋める置き場が、ページの部品を決める。承認カードが差し戻す先のステップを尋ねるのはデータに `/send_back/to` があるときだけで、申請書がだれの代わりかを尋ねるのは `/submit_for` が空でないときだけ、というふうである。承認カードは、A2UI の承認カードと同じく、申請者と、代わりに申請を出した人の名前を `/people` から見せる。データにこの二人の名前が無ければ（二人を見せない承認カードのテンプレート）、ページが自分で `Lookup` に尋ねる。ページは `/upload` も `/refused` も読まない。ファイルはページのフォームが自分で送り（4.3）、断りは、もう一度見せるときの読んだ結果で受ける（4.4）。

アドレス（`Back`）を渡せば、どのページも、頭の下に、前のページへ戻るリンクを置く。承認カード、一覧、新しい申請のフォームからはホームへ（「← ホームへ戻る」"← Back to the start page"）、履歴と、出し直しのフォームからはチケットの承認カードへ（「← 申請へ戻る」"← Back to the request"）戻る。

### 3.1 申請書

`<form method="post" novalidate>` が一つあり、次を持つ。

- 隠しフィールド：`_surface`（画面の面。`<種類>.form.<x>`）、`_at`（ページを見せた時刻）、もう一度申請するときは `_revision`（ページが見せるチケットの版。JSON）、トークンを渡したときは `_csrf`。
- 先頭に、見えないボタン（`_do` = `stay`。`DoStay`）。入力の中で Enter を押したときに押されるボタンである。その投稿には 204 No Content で答え（`Reading.Stay`。投稿は何も読まず、ファイルも預からない）、ブラウザはページを本人が離れたときのまま残す。打った値も、選んだファイルも、フォーカスの場所もそのままである。だから、Enter で申請が送られることも、行の最初のボタンが押されることもない。スクリプトがあれば、Enter は何も送らない。
- `requester`：`/submit_for` から選ぶ部品（空なら見る人自身の申請）。`/submit_for` があるときだけ置く。
- 申請者が入れるフィールドごとの部品（値は `f.<フィールド>`）。計算する数は `<output>` で見せ、明細は `<fieldset>` の中に行ごとの `<fieldset>` を置く。
- `comment`。
- 見る人が押せるボタン（`/can`）。どれも `<button name="_do" value="button.submit">` の形である。

フィールドがページにあることは、隠しフィールド `s.<フィールド>` で示す。スクリプトは、`shown when` が成り立たないフィールドを、部品ごと disabled にして隠す。すると値も印も送られないので、読む側はそのフィールドが隠れていたとわかる（4.1）。

| フィールドの型 | 部品 | 読んだ値 |
|---|---|---|
| `text` | `<input type="text">` | 両端の空白（Unicode の `White_Space` の 25 字。種類が理由を読むのと同じで、U+0085 は空白、U+FEFF と U+001C は空白でない）を除いた文。何も残らなければ値なし |
| `long text` | `<textarea>` | `text` と同じ |
| `number`、`money[…]`、`rate[step …]`、`mass[kg]` など | `<input type="text" inputmode="decimal">` と、後ろの単位 | 単位の刻みの整数（5 章） |
| `date` | `min` と `max` を付けた `<input type="date">` | `YYYY-MM-DD`（`YYYY/M/D` も読む） |
| `choice`、`choice from <規則>.<列挙>` | 選択肢の `<select>`。先頭は空 | 選んだ値の ASCII の名前 |
| `choice from <マスタ>` | `Picks.Masters[<パス>]` の `<select>`。並べる物が無ければ、行のキーを打つ入力。`Picks.Find` に探す方法があれば、名前でも探せる（3.1.1） | キー |
| `person`、`team` | `Picks.People`（チームなら `Picks.Teams`）の `<select>`。並べる物が無ければ、ID を打つ入力。マスタと同じく名前でも探せる | ID |
| `attachment` | `<input type="file">`。添付してあるファイルの ID を `a.<フィールド>` に置き、外すためのチェックボックス `d.<フィールド>` を付ける | ファイルの ID（4.3） |
| `bool` | `<input type="checkbox">` | `true` か `false` |
| `rows` | `<fieldset>`。行ごとに隠しフィールド `r.<明細>` が行の印を持ち、行のフィールドは `f.<明細>.<印>.<フィールド>`。行を足すボタンと消すボタンを付ける | 送られた順の行の並び。どの行も、入れたフィールドを持つ |

どの部品にも `<label for>`（まとまりには `<legend>`）があり、検査の文言の一覧を `aria-describedby` で指し、検査に通らなければ `aria-invalid` を付ける。いつも必須のフィールドは、ラベルにそう書き、`aria-required="true"` を付ける。フォームには `novalidate` を付ける。ブラウザ自身の検査はブラウザの言語で話し、条件も知らないので、ページの検査に言わせる。

`Worked` があれば、ページは組むたびに、フォームが計算する物を種類の入口に聞く。見せ直すときは送られた値で、そうでなければ最初の値で聞く（明細は、最初に置く空の行の数で数える）。条件が成り立たないフィールド（`shown` が false）は、`hidden` を付け、中の部品を全部 disabled にしてページに置く。スクリプトがあってもなくても、ブラウザはそのフィールドを何も送らない。条件が成り立つようになれば、スクリプトがまた見せる。条件が成り立つフィールド（`shown` が true）は、ラベルの下の添え書きなしで見せる。答えが必須とするフィールド（`required` が true）は必須の印と `aria-required` を付け、必須でないとするフィールドにはどちらも付けない。計算する数は答えの値を見せ、決まらなければ「—」を見せる。答えが何も決めない所（null か、`Worked` が無いとき）は、下に書くとおりに見せる。人が打つたびに、スクリプトが同じことを決め直す（必須の印を決める関数は `data-required-when` が名指す）。入口の失敗はサーバーがログに書く。ページは `Worked` が無いときと同じに組み、送られたときに検査する。

計算する数は、フォームが計算するとおりに見せる（`functions.js`）。計算する日（暦から出す日）と、明細の行の計算するフィールドは、A2UI の申請書と同じく申請書では計算しない。それらは承認カードが見せる。範囲のある、行の計算するフィールドは、明細のまとまりで検査する。API がある行のそれを断ったとき（`lines[0].subtotal`）は、ページはその行のセルを見せ、通らなかった検査をその横に見せる（4.4）。

見せる行の無い明細は、フォームが求める行の数の下限（`count_min`）だけ空の行を置いて始める。A2UI の申請書が明細の行を下限の数に保つのと同じで、行が無くてよい明細は行なしで始まる。もう一度見せるページは、送られた行を見せる。

JavaScript が無ければ、フィールドは全部見せる。条件で見せるフィールドは、ラベルの下に「この申請に当てはまるときだけ入力してください。」と書き、条件で必須になるフィールドには「申請によっては必須です。」と書く。明細の行は、フォームを送ってページをもう一度見せるボタンで足し、消す（`_do` = `row.add:<明細>` か `row.remove:<明細>:<印>`）。このとき操作は作らない。見せ直したページは、フォーカスを、足した行の最初の部品に、行を消したあとは明細の見出し（`<legend>`）に置く（3.6）。

#### 3.1.1 名前で値を探す

サーバーは、選ぶ部品の値を、自分で決めた数まで並べる（web のパッケージは 1,000 件）。それより多い部品は並べず、`Picks.Find` に、その値の中から探す方法を持たせる。入れた言葉のどれもが、ID かキーか名前に含まれる値を、API の探す操作と同じく近い順に探す（web のパッケージは `server.Find` で探す）。部品は、並べる物の無い部品と同じく ID かキーを打つ入力で、後ろに「検索」のボタンが付き、「ID を入力するか、名前の一部を入れて「検索」を押してください。」（マスタなら「コード」）と書く。

```html
<div class="field find" id="field-in-person" data-field="person" data-type="person" data-find="/a2ui/find/people?lang=ja">
<label for="in-person">使う人</label>
<p class="hint" id="hint-in-person"><span>ID を入力するか、名前の一部を入れて「検索」を押してください。</span></p>
<span class="find-box"><input type="text" id="in-person" name="f.person" value="営業担当 3" … /><button type="submit" name="_do" value="find:person" class="plain find">検索</button></span>
<p class="named" id="named-in-person" hidden="hidden"></p>
<div class="found" id="found-in-person">
<p class="status" id="status-in-person" role="status" tabindex="-1" autofocus="autofocus">「営業担当 3」で見つかりました。一つ選んでください。</p>
<ul><li><button type="submit" name="_do" value="choose:person:e1203" class="plain" data-value="e1203" data-name="営業担当 3">営業担当 3（e1203）</button></li></ul>
</div>
…
</div>
```

- **スクリプトが無ければ**、「検索」はフォームを送り（`_do` = `find:<場所>`）、ページは操作を作らずにそのまま見せ直す。見せ直したページでは、入力の文が値でない部品が、その言葉で見つかった物を 20 件まで（`FindShown`）並べる。どれも、その値を選ぶボタンである（`_do` = `choose:<場所>:<値>`。明細の行の場所は `<明細>.<印>.<フィールド>` で、印は送られたとおり）。押すと、その値を入れてページを見せ直す。何も見つからなければそう言い（「「zzz」では見つかりませんでした。」）、20 件を超えれば言葉を足すように言う。ほかの理由で見せ直したページ（検査に通らない、API が値を断った）でも、入力の文で見つかる物を並べる。「検索」のあとに見せ直したページは、見つかった物を言う行に、値を選んだあとはその入力に、フォーカスを置く。
- **スクリプトがあれば**、打っているあいだに（最後のキーから 0.25 秒で）、「検索」と Enter ではすぐに探す。探すのは `data-find` に `&q=` と言葉を付けたアドレスで、画面の `/find`（サーバーが `Serving.Find` で渡すアドレス）に `/people`、`/teams`、`/masters/<パス>` のどれかと `?lang=` を続けた物である。見つかった物は、スクリプトの無いページと同じく部品の下に並べ、ボタンは送らずに値を選ぶ。`/find` の無い画面では部品に `data-find` が無く、「検索」はスクリプトが無いときと同じくフォームを送る。入力メソッドで変換しているあいだの Enter は、入力メソッドの物である。見つかった物を言う行は `role="status"` で、変わるとスクリーンリーダーが読み上げる。後ろのボタンまでは読み上げない。探す操作が受け付けるより長い言葉（200 コードポイント。`FindLongest`）は送らず、その行で「検索する言葉は200字以内にしてください。」（"Search with words of 200 characters or fewer."）と言う。サーバーが 400 を返したときも同じ文を言う。入力には `maxlength` を付けない。ID やキーも入れる入力で、`maxlength` は UTF-16 で数え、貼り付けた文が黙って切られるためである。
- **値の名前。** 見つかる値そのもの（ID かキー）を持つ部品は、入力の下にその名前を書く（`named-…`）。入力の `aria-describedby` は、これと、見つかった物を言う行（`status-…`）を指す。名前が値そのものと同じ値（探す操作は、その名前をそのまま返し、ラベルは値だけにする）は、スクリプトがあってもなくても、名前を書かず、選ぶボタンにも名前を持たせない（`data-name` は空）。

スクリプトが言う文言は、フォームに JSON で置く（`data-find-words`。`found`、`none`、`more`、`failed`、`long`。言葉の入る所は `{}`。それと `longest`）。読み取りは、部品の値が見つかる値かを確かめない。ID やキーでない値は API が断り（`form`）、見せ直したページが、その文で見つかる物を並べる。

### 3.2 承認カード

チケットの頭（題、番号、状態、ステップ、申請者、代わりに申請した人）、説明が見せるとおりの申請の値（選択はラベルで、金額は単位を付けて、明細は表で、ファイルは `/files` のリンクで。条件で隠れたフィールドは値を持たないので出さない）、経路（ステップごとの状態、部分ごとの決め方、承認者、答え）を見せる。見る人が何かできるときは `<form>` が一つあり、承認者が直すフィールド（`f.<フィールド>`。申請書と同じ部品で、保存するボタンを付ける）、コメント、差し戻す先のステップ（`send_back_to`。カードが送るときだけ）、足す承認者（`approver`。待っている部分ごとにボタンを置き、`_do` = `button.add_approver:<部分>`）、引き継ぐ承認者（`hand_over_of`、`hand_over_to`）、ボタンを持つ。人を並べないときは、これらの部品も、フィールドと同じく人を探す（3.1.1）。カードは A2UI の承認カードと同じ物を見せるので、ブラウザで承認する人も同じ申請を読む。

経路は、チケットの状態と合わせて言う。チケットは、止まったときの段階と状態を持ち続けるからである。進行中の申請では、答えを待つステップは「回答を待っています」、その部分は「待っています」と言う。ほかの申請では、止まったステップは、カードの頭と同じ文言でチケットの状態を言う（「保留中」「申請者に戻っています」「却下されました」など）。待っていた部分は、まだ続きうるあいだ（保留中か、申請者に戻っているとき）は「まだ決まっていません」、終わったあとは「決まる前に終わりました」と言う。却下された申請では、もう承認に届かない部分が「却下されました」と言う。終わった申請が着かなかったステップは「ここまで進みませんでした」と言う。あとのステップの承認を待ち（`same approver approves once, at the last stage`）、同じ名前の二度目のステップとして始まったステップ（ringi の DESIGN 7.1）は「下の同じステップに移りました」と言い、どうなったかは二度目のステップが言う。要約のステップの部分は、ステップが済めば「エージェントに頼みました」と言う。進行中か保留中の申請がいるステップが今のステップで（`aria-current="step"`）、スタイルシートは、そのステップと、その中のまだ決まっていない部分を目立たせる。

申請を出し直すフォームのアドレス（`Resubmit`）を渡せば、申請者に戻っているチケットのカードは、頭の下でそう言い、フォームへのリンクを置く（「内容を修正して再申請する」"Edit it and submit again"）。チケットが差し戻した人を持っていれば（`sent_back_by`）、差し戻されたと言う（「この申請は差し戻されています。」"This request has been sent back."）。持っていなければ、取り下げられて戻ったと言う（「この申請は取り下げられ、申請者に戻っています。」"This request has been withdrawn, and is back with its requester."）。状態はどちらも同じ `with_requester` である。アドレスは、出し直せる人にだけサーバーが渡す。ほかの状態のチケットのカードは、アドレスを渡されても何も言わない。

`Worked` があれば、カードの値はチケットのフォーム（`edited` は null）で決める。条件が成り立たないフィールドは出さず、条件が成り立つフィールドは値が無くても出し（「—」）、計算した値（チケットに残らない明細の小計も）は答えの値を見せる。承認者が直すフィールドは、直したあとのフォームが決めるとおりに見せる。直した値を `edited` に入れて聞く（空にしたフィールドは入れない）。

説明がステップの操作に理由を求めているとき（`comment_required`）は、その操作のボタンに、理由の要るボタンの印（`data-scope="reason"`）を付け、コメントの検査に「理由をコメントに書いてください。」（"Write the reason in the comment."）の行を足す。A2UI の承認カードのボタンと同じ文言である。スクリプトがあれば、理由の無いままではそのボタンを送らない（`functions.js` の `commentGiven`）。スクリプトが無ければ、読む側が同じ所で止め（4.1）、コメントの横で言う。

A2UI の承認カードで直しを保存するボタンは、承認者が直すフィールドだけでなく、直したあとのフォーム全体を検査する。範囲のある計算した値や、直しで変わる条件で必須になるフィールドも検査する。ページも同じにする。直さないフィールドの検査は、直す部品のまとまりの中、フィールドの下の一覧（`edit-rest`）に並べ、通らない物をスクリプトが言う。

### 3.3 一覧と履歴

一覧は `<table>` で、番号（`Open` へのリンク）、状態のバッジ（3.5）、ステップ、申請者か代わりに申請した人（下に書く）、短いフィールドを並べる。短いフィールドは、明細、長文、ファイルのどれでもなく、条件で見せる物でもないフィールドである。申請者が入れるフィールド（A2UI の一覧も見せる）と、フォームが計算するフィールド（申請の合計など。チケットが持つ値で、A2UI の一覧は見せない）がある。どのステップにもないチケットのステップの列は、申請者に戻っているあいだは申請者（「申請者」）、ほかは「—」である。本人の申請の一覧（`Of` が `ListMine`）は `screens` の `mine` の画面（`Set.Mine`）から作り、その画面と同じく、四つ目の列は代わりに申請した人である（「代わりに申請した人」。申請者が自分で出した申請では「—」）。ほかの一覧は `list` の画面（`Set.List`）から作り、四つ目の列は申請者である。見出しは種類の題で、`Of` があれば、だれのチケットかも言う（「経費の申請：あなたの対応を待っている申請」「経費の申請：あなたの申請」）。`More` があれば、表の下に、もっと前のチケットへのリンクを置く（「もっと前の申請を見る」）。チケットの無い一覧は「申請はありません。」と言う。履歴は行を順に並べたリストで、いつ、何をしたか、ステップ、だれが、だれの代わりに、コメント、空にしたフィールド、注記を見せる。時刻は `History.Zone` で見せる。カードが答えを `Card.Zone` で見せるのと同じで、サーバーはどちらにも種類のゾーンを渡す。カードと履歴は、一つの承認の時刻を同じに言う。

### 3.4 ホーム、帯、知らせ

ホーム（`Home`）は三つの部分を持つ。どれも種類を題で並べたリストで、どの種類もリンクである。本人を待っているチケットの種類とその数（「(3)」「3件」）、本人が出せる申請の種類、本人が申請を出した種類である。本人が申請を出した種類には、状態ごとの数を添える（`Entry.States` と `Entry.SentBack`。「差し戻し 1・再申請待ち 1・承認待ち 3」"1 sent back, 1 to be resubmitted, 3 waiting"）。本人に戻っていて本人を待つ物を先に、次にほかの開いている物、終わった物の順に並べ、一つも無い状態は出さない。同じ題の種類が二つある部分は、題のあとに種類の名前を見せる（「経費の申請 (expense_ja)」。`Entry.Name`）。種類が一つも無い部分は、そう言う（「あなたの対応を待っている申請はありません。」「あなたが出せる申請はありません。」「まだ申請していません。」）。`Home.Admin` があれば、終わりに管理のページへのリンクを置く。

一つ目と三つ目の部分の種類は、その下にチケットをいくつか並べられる（`Entry.Tickets`）。行には、番号（チケットの承認カードへのリンク）、状態のバッジ（3.5）、ステップの文言、行が挙げる人、値の短い行（`TicketInfo`。フォームが計算した数、次に日付を、ページが見せるとおりに二つまで。「1,200,000円・2026-11-16」）を置く。どのチケットを並べ、だれを挙げるかは、サーバーが決める。`StageIn` は、ページが言うとおりのステップの文言と、その言語を返す。ページの言語でないステップは、`EntryTicket.StageLang` にその言語を持つ。

今は効いている版が無く、ある日から出せる種類（`Entry.From`）は、リンクの無い行として日付を言う（"Leave request (may be made from 2027-04-01)"、「休暇の申請（2027-04-01から出せます）」）。`Offered` は、そういう種類の新しい申請のページを作る。題と、出せる日の一文（`screens.OfferedWords`。A2UI の申請書とエージェントのツールも同じ文を言う）と、先へ進むリンクを持つ。

どの種類を並べるか、どのアドレスにするかは、サーバーが決める。`Title` は、ページが言うとおりの種類の題（その言語のラベル、無ければ書いた題）を返す。`TitleIn` は、同じ題と、その題の言語（尋ねた言語のラベルが無ければ、種類を書いた言語）を返す。`Masters` は、種類のフィールドが行を選ぶマスタ、つまり `Picks.Masters` が行を並べてよいマスタを返す。題がページの言語でない項目（ほかの言語で画面を書いた種類や、ページの言語のラベルが無い種類）は、`Entry.Lang` にその言語を持ち、リンクの `lang` に付ける。スクリーンリーダーは、題を書いた言語で読む。

帯（`Bar`）は、ページの言語の `<nav>` 一つで、名前は付けない（スクリーンリーダーは役割で呼ぶ）。サーバーが、知らせも含めて見せるページ全部に置けるように、ページとは別に作る。ホームへのリンク（「ホーム」）、ログインしている人（「営業担当 1 でログインしています」）、ほかの言語のページ（どのリンクもその言語で名前を書き、`lang` と `hreflang` を付ける）、`SignOut` へ送ってログアウトするフォームを持つ。渡されなかった物は置かない。

知らせ（`Notice`）は、求められたページの代わりに見せる、一つのことを言うページである。リンクを渡されれば、言うことのあとに、先へ進むリンクを付ける。

| `what` | 題 | 言うこと | リンク |
|---|---|---|---|
| `NoticeNotFound` | 見つかりません | このページは無いか、あなたには見る権限がありません。 | ホームへ戻る |
| `NoticeNoPerson` | ログインしていません | このページを使うには、ログインしてください。 | ログインする |
| `NoticeBadPost` | 送った内容を読めませんでした | ページを開き直してから、もう一度送ってください。 | ホームへ戻る |
| `NoticeTooLarge` | 送った内容が大きすぎます | 送った内容が、サーバーの受け付ける大きさを超えています。小さいファイルを添付してください。 | ホームへ戻る |
| `NoticeFailed` | サーバーのエラー | サーバーでエラーが起きました。しばらくしてからもう一度試してください。 | ホームへ戻る |

知らせをどのステータスで、いつ送るかは、サーバーが決める。

### 3.5 文言

ページは英語か日本語で、A2UI の画面の文言（ringi の `crates/ringi/src/screens/a2ui.rs`）を使う。説明のラベル（`labels <言語>`。無ければ書いた題）、ボタン（`Submit`、`申請する`）、状態、履歴の行、検査（`Choose Category.`、`種別を選んでください。`、`Enter Price (Items) from 1 JPY to 1,000,000 JPY.`）である。日本語の文に置く名前（ラベル、人の名前、検索に打った言葉）は、フレームワークのほかの日本語の文（MCP のツールの答え、サーバーが書く断りなど）と一つの決まりで置く（パッケージ `internal/jatext`）。ASCII で終わるか始まる名前は、仮名や漢字との間を空白で区切り（A2UI の画面と同じく `Kind of leave を選んでください。`）、全角の約物には空白を置かずに付ける（`Leave request：あなたの申請`、`e1101（e3101 の代わりに）：承認`）。数は名前ではなく、単位も A2UI の画面の書き方のままにする（`1円から1,000,000円まで`、`10 MB以下`）。A2UI の画面に無い文言（数の読み方、経路の状態、JavaScript の無いページの案内、ホーム、帯、知らせ）は、このパッケージが同じ調子で書く。断りは `screens.RefusalWords` の文で言う。A2UI の画面の操作も、同じ文を言う。英語と日本語のほかの言語では、ページ自身の文言は英語で、種類の文言は種類のとおりである。

種類の説明の文言をページの言語でない言語で見せるとき（ringi の DESIGN 4.8。ページの言語の `labels <言語>` が無い題、フィールドのラベル、選択肢、ステップ、決め方）は、それを単独で見せる所で、種類を書いた言語の印（`lang`）を付ける。見出し、フィールドのラベル、表の列、値のラベル、選択の選択肢（`<option lang>`）、値として見せる選択肢、ステップ、決め方、履歴の行で空にしたフィールドである。スクリーンリーダーは、それをその言語で読む。ページのほかの所はページの言語で、印は付けない。ページの文の中に置いた名前にも印を付け、そのまわりの文には付けない。検査の文、フィールドでの断りの文、受け付けないファイルの文、計算した値のために直すフィールドの文、明細の行の見出し（`<span lang="en">Items</span> の2行目`）、もう一度見せたページの頭の行（検査の文を言う）である。文は名前ごとにその言語を持ったまま組み（フレーズ）、ページはそのフレーズを書く。ページの文に、名前を文字として持つ物は無い。スクリプトが書く物も印を保つ。ボタンが検査の失敗を見つけたときにフォームの頭に出す行は、検査の文をページにあるとおり印ごと写す。明細の行の見出しは行の番号を別の部分（`<span class="row-n">`）に持ち、スクリプトは行を足すか消したときにそこだけを書き直す。名前を持つ属性は無い（属性には印を付けられない）。印を付けられない所は一つで、文字しか持てないページの `<title>` である。題は見出しの文言を印無しで言う。

チケットの状態は、承認カードの頭では A2UI の画面の文言で言い（「進行中」"In progress"）、チケットをいくつも並べる一覧とホームでは、短い言葉のバッジで言う（「承認待ち」「保留」「承認」「却下」「取り下げ」「期限切れ」、"Waiting"、"On hold"、"Approved"、"Rejected"、"Withdrawn"、"Expired"）。申請者に戻っている物は、チケットが差し戻した人を持っていれば（`sent_back_by`）「差し戻し」"Sent back"、持っていなければ、申請者が取り下げた物なので「再申請待ち」"To be resubmitted" である。どちらの書き方も状態そのもの（`data-status`）を持ち、スタイルシートはそれで色を付ける。言葉も同じことを言うので、色が見えなくても読める。承認カードの経路の、ステップの状態と部分の状態も、それぞれ持つ（`data-phase`、`data-state`）。

値は型と単位から見せ（5 章）、A2UI のテンプレートの書式は使わない。12.5% の率は `12.5%` と見せる。5 桁以上の数は 3 桁ごとにカンマで区切り、4 桁以下は区切らない。ritsu が検査の文に数を書くのと同じで、`2000`、`20,000`、`1,000,000 JPY` となる。

### 3.6 HTML

ページは `html/template` で書くので、どの値も置かれた場所に合わせてエスケープされる。インラインのスクリプトとスタイルは無い。読み込むのは、スタイルシート一つ（`page.css`）と、モジュールのスクリプト一つ（`page.js`。一式の `functions.js` を同じアドレスから読み込む）だけで、画像もフォントも読み込まず、スクリプトから通信もせず、`eval` も使わない。`Options.Assets` がサーバーと同じオリジンなら、`Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; form-action 'self'` のもとで動く。マークアップは整形式の XML でもあり、試験はそれを読む。見せるだけの文（履歴のコメントと注記、カードの値）にある制御文字は、その字の絵（U+2400 から。DEL は U+2421）で見せる。制御文字で書いた理由もそのとおり見え、ページも XML のままである。

`Document` はページ全体を作る。帯（`Page.Bar`）を置き、続けて画面を文書のメインコンテンツ（`<main>`）一つとして置くので、スクリーンリーダーはすぐ画面へ行ける。`<meta name="color-scheme" content="light dark">` も置く。ページは、キーボードだけでも、スクリーンリーダーでも、どの文字の大きさでも、明るい配色でも暗い配色でも使えるように作る。

- page.css の色は、明るい配色でも暗い配色でも（`prefers-color-scheme`）、文字はそれを書く背景のどの色とも 4.5:1 以上、入力や押す物の枠線（`--edge`）とフォーカスリング（`--focus`。3 px）はまわりの色と 3:1 以上である（WCAG 2.2 の 1.4.3 と 1.4.11）。`--line` は、ページを区切るだけの線に使う。日付の入力は、年・月・日のどこかにフォーカスがあるあいだ、フォーカスリングを見せる。
- 文字の大きさはブラウザの設定のとおり（`100%`）で、ピクセルの数では決めない。
- おかしい所を言って見せ直したページは、ページが来たときにページの頭にフォーカスを置く（`autofocus`。スクリプトもそこへ置く）。ページの上だけで働くボタン（行を足す、消す、値を探す、選ぶ）のあとに見せ直したページは、そのボタンが働いた部品にフォーカスを置く（3.1、3.1.1）。ページが来たときにフォーカスを置く所は、一つまでである。フィールドで押した Enter では、ページを見せ直さないので、フォーカスは動かない（3.1）。
- 承認カードのフォームは自分の見出し（「できる操作」）を持ち、それを名前にする。承認者を足すボタンは、どの部分に足すかを `aria-describedby` で言う。

### 3.7 管理のページ

`AdminPage` は、管理の五つのページ（コアの DESIGN 13.7）を、`Admin.What` に応じて作る。その人が使える部分（`AdminHomePage`）、種類とその版と、その人が切り替えられる版ごとの切り替えのフォーム（`AdminKindsPage`）、組織の最新のデータと、ソースのデータを確かめるボタンと、アップロードするファイル（`AdminOrgPage`）、下書きの日ごとの差と、理由と、取り込むボタン（`AdminDraftPage`）、記録の絞り込みと、一ページの行と、同じ行の CSV へのリンク（`AdminRecordsPage`）である。どのページも、サーバーが管理の操作の答えで埋め、アドレスもサーバーが決める。どのページも、フォームを含めてスクリプトが無くても動き、英語か日本語で、ほかのページと同じ帯と `<head>` を持つ。アドレス（`Admin.Back`）を渡せば、頭の下に、管理の最初のページへ戻るリンクを置く（「← 管理へ戻る」"← Back to the administration"）。したこと（`Done`）、投稿の断り（`Refused`）、問題（`Problem`）、組織のデータの問題（`Problems`。それぞれファイルと行を付ける）は、ページの頭で言う。どれも、データのどの名前とも、記録の行のどの値とも同じく、自分の向きを持つ要素（`<bdi>`）の中に置く。あとに続く文字の向きを変える文字が、ページの文の向きを変えないためである。投稿のキーは、ほかのページと同じく、ページを見せた時刻（`Now`）を読む（4.5）。

切り替えの日は日付の入力で、ブラウザが、版を始められる最初の日（`AdminVersion.FirstDay`：今日か、使える最初の日のほうがあとならその日）から最後の日までに限る。人がこれらのフォームで間違えうることは、サーバーが操作を送る前に、ページがその言語で言う（`AdminSays`。定数 `AdminBadDay` など）。`YYYY-MM-DD` と読めない日、今日より前の日、版を使えない日（使える最初と最後の日を添える）、500 字より長い理由と、残せない文字を持つ理由（その文字は `U+XXXX` で言う）、選んでいないファイル、サーバーが受け取るより大きいファイル、その日の取り込みの数を使い切ったこと（待つ分数を添える）である。最後に決めるのはサーバー自身の確かめで、その文は API の文である。

## 4. 投稿を読む

`ReadForm` と `ReadCard` は、ページを作ったときと同じ入力（サーバーのチケットと、見る人ができること `Can`）、投稿、添付ファイルを預かる `Keeper` を取る。投稿の面（`_surface`）はページの面（新しい申請なら、その種類の新しい申請書の面）で、押したボタン（`_do`）はページにあるボタンでなければならない。読む側は、ボタンが送る値を作り（4.1）、`screens.Action`（名前はボタンのイベント、部品はボタン、時刻は `_at`、中身はその値）にする。それを `screens` が操作にする。ページの投稿でない物（ほかの面か面が無い、ボタンが無いか、どの画面にも無いボタン、読めない時刻か版）は `ErrPost` である。

見る人が今は押せないボタン（`/can`）は実行しない。今のチケットを見せているページ（`_revision` がチケットの版と同じ）で押したなら、「今は、この操作はできません。」と書いてページをもう一度見せる。チケットが最後に変わる前に見せたページ（別のタブや、戻ってから送り直したページ）で押したなら、API は古い版として断るはずなので、読んだ結果をその断りにする。`Refusal()` は `stale` を返し、もう一度見せるページは、今のチケットを、打ったコメントと `stale` の文（4.4）を付けて見せる。コメントは版を持たないので、このように読まない。

ボタンが無くなったのは、この投稿そのもののせいかもしれない。スクリプトの無いブラウザは、二度押したボタンを二度送り、戻ったページからはもう一度送れる。そこで、読んだ結果は、投稿が作る操作も、投稿のキー（4.5）と一緒に `Sent` に持つ。サーバーはそれを実行せず、同じキーの同じ操作を前に受け付けていれば（`Server.Replied`。本体の DESIGN 8.1）、そのときと同じに答える。値が読めないか、確かめに落ちた投稿には `Sent` が無い。新しい申請の投稿にも無い。申請しても、そのボタンは無くならないからである。サーバーが投稿に答えたあとは、`Operation` と同じく nil になる。

### 4.1 値

- **新しい申請**（`submit`）：`requester`（自分の申請なら null）、`form`（ページにあり、値を持つフィールド。投稿に無いフィールドは隠れていた物）、`comment`。
- **もう一度の申請**（`resubmit`。ringi の DESIGN 7.3 と 12.4）：`form` は、ページが見せたフォーム（`/before`）から値が変わったフィールドだけを持つ。`clear` は、そのフォームが値を持っていて、今は空か、隠れたフィールドの名前を並べる。明細は `clear` に入れない（行の無い並びとして送る）。隠れたフィールドの値は送らない。
- **承認者の直し**（`edit`）：承認者が入れるか直すフィールドについて、ページが見せたチケットのフォームと比べて同じことをする。`fields` と `clear` である。
- **ほかのボタン**：チケットの番号（入力の、サーバーが指すチケットから）、ページが見せた版（`_revision`）、`comment`、ボタンがほかに送る物（`to`、`approver` と `part`、`of` と `to`）。

どれも、同じフォームで `functions.js` が送る値（`<種類>.given`、`.changes`、`.cleared`、`.edits`、`.edits_cleared`）と同じで、試験が二つを突き合わせる。文、長い文、コメントは両端の `White_Space` を除く。数、日、ID は、これまでどおり `String.prototype.trim` が除く物を除く。

投稿の版が今のチケットの版なら、ページが見せたフォームは、今のチケットのフォームである。ほかの版のチケットを見せたページが見せたのは、チケットがそのとき持っていたフォームで、読む側は、入力の `FormAt` に尋ねる（サーバーは `Server.FormAt` で答える。本体の DESIGN 8.1）。投稿が変えた物は、そのフォームとの違いになる。だから同じ投稿は、何度送っても同じ本文になり、同じキー（4.5）になる。その版のフォームが分からないとき（`FormAt` が nil か、nil を返した）は、ボタンを今見せているなら、今のフォームと比べて読み、サーバーが `stale` で断る。見せていなければ、`Sent` は無い。

### 4.2 サーバーでの検査

読む側は、操作を作る前に、説明だけで決まることを、スクリプトが見せるのと同じ文言で検査する。型に合う値か（単位の刻みの数、ある日、選択肢の一つ）、いつも必須のフィールド、文の長さと明細の行の数、範囲、コメントの長さ（コメントのボタンならコメントがあるか。ステップが理由を求める操作（`comment_required`）なら理由があるか）、足す承認者と引き継ぐ承認者、見る人が自分では申請を出せないときのだれの代わりか、である。一つでも通らなければ `Operation` は nil で、`Problems` が部品ごとにそれを言い、ページは打った値のままもう一度見せる。種類の規則が要ること（条件、範囲のある計算した値、その日のマスタの行、組織の人、暦の開いている日）は、どの投稿とも同じく `next` が検査する。スクリプトは、`functions.js` が検査することを全部、送る前に検査する。

### 4.3 添付

ファイルのあるフォームは `multipart/form-data` で送る。読む側は、選んだファイルを一つずつ `Keeper` に渡し、返った ID を値にする。`Keeper` はサーバーが投稿ごとに作り、ファイルを送った人の物として預かる（`KeepFunc` で関数から作れる）。ページをもう一度見せるときはその ID を `a.<フィールド>` に置くので、同じファイルを二度選ばなくてよい。チケットが持つファイルは、`d.<フィールド>` にチェックを入れない限り残る。隠しフィールドは書き換えられるので、投稿が書く ID が、その人が添付してよいファイル（その人が預けた物か、チケットが持つ物）かどうかは、サーバーが確かめなければならない。

ページの `Keeper` は、同じページの同じファイルには、同じ ID を返す（`web` の `Handler.Keeper` がそうする。`web` の DESIGN 9.3）。ID は本文に入るので、ファイルを二度預かると、ファイルのあるフォームを二度送った人は、二つの操作をし、二つの申請を出したことになる。

`Keeper` は、預からないファイルには `*FileRefusal` を返す。`Max` バイトより大きいファイル（`TooLarge`）、中身がタイプのとおりでないファイル（`Content`）、どの申請にも付いていないアップロードを一人あたりの上限まで持っている人のファイル（`TooMany`）、受け付けない種類のファイルである。読む側は、そのファイルのフィールドでそう言い（「領収書のファイルが大きすぎます。10 MB以下のファイルを選んでください。」「領収書のファイルを受け付けられませんでした。どの申請にも付いていないファイルが、一人あたりの上限の50個に達しています。申請に付かないファイルは、送ってから7日で消えます。」「領収書には、この種類のファイルを添付できません。」）、何も送らず、そのフィールドが前に持っていたファイルを残す。`Keeper` のほかのエラーは、読む側のエラーになる。

### 4.4 API の答え

API は、受け付けない操作に三通りで答える。ページはどれも言う。

- **断り**（409、`{"refused": kind, "text": …, "text_ja": …, "at": …}`。ringi の DESIGN 12.4）：API が答えた `screens.Refusal` で `rd.Refused(refusal)`。`Again: rd` でもう一度見せるページは、断りの種類の一文（`screens.RefusalWords`。web の断りの答えも、A2UI の画面のために同じ文を持つ）を頭で言い、断りの文は、ページの言語の物（`Refusal.In`）を、申請を管理している人向けの詳細として、その下に畳んで見せる。断りの文は、イベント、フィールド、種類の行を、種類が書いたままの名前で言うからである。`form` の断りは、その場所（`at`。`Refusal.Place` で読む）が指す部品で、部品のラベルから作ったページの文で言う。フィールド（`trip_to`）、明細の行のフィールド（`items[1].price`。行は 0 から数え、部品は `items.1.price`）、明細の行でフォームが計算するセル（`lines[0].subtotal`。小計が範囲の外になった最初の行）、明細（行のフィールドを指さない明細の中の場所。行の数の `lines`）、範囲のある計算した値（その検査の文言で言う）である。行で計算するセルは、その行のセルの横で、セルの範囲と、値を計算するのに読むフィールドの言葉で言う。行はふだんそのセルを見せず（`functions.js` が計算するのはフォームの値で、行の値ではない）、断られたときだけ見せる。`comment` の断り（空のコメント、長すぎるコメント、理由を求める操作で理由が無いとき）は場所を持たず、どのボタンで送っても、コメントの横で言う。コメントが書いてあれば受け付けなかったことを、コメントのボタンなら「コメントを書いてください。」を、ほかのボタンなら「理由をコメントに書いてください。」を言う。どこで言うかは、断りの種類と場所だけで決まる。どの部品でも言わない `form` の断り（場所を指さない物。コメントのボタンでも同じ。フォームのフィールドでない場所、ringi の書き方でない場所（`items.1.price`））は、ページの頭で言い、頭は「受け付けられない値があります。入力した値を確かめてください。」と言う。`stale` で断られたあとは、今のチケットを、打ったコメントを残して見せる。
- **API が読めなかった本文**（400、応答の `Problem`）：`rd.Invalid(problem)`。値は、生成した入口の文で言われる。その文は、本文が入る引数で場所を言う（``The argument `submit.form.items[1].price` of `start` is "x", and must be an integer``。日本語の文もある。コアの DESIGN 7.2）。入口が見ない物は、フレームワーク自身の文で言われ、その文は本文の中の場所で始まる（`form: "color" is not one of its fields`）。ページはどちらからも本文の中の場所を読み（`submit.` と `event.<イベント>.` を除く）、その場所が指す部品（`form.<フィールド>`、`fields.<フィールド>`、明細の行のフィールド、`comment`、`requester`、`approver`、`of`、`to`）で言い、どれでもなければページの頭で言う。ページ自身の投稿には、この答えは来ない。値を読んで検査してから送るからである。
- **今は受け付けないコメント**（429、応答の `Problem` と、その `Retry-After` の秒数）：`rd.Limited(problem, wait)`。もう一度見せるページは、`screens.LimitedWords` の文で、その秒数だけ待ってから送り直すように、`wait` が 0 なら、その人のコメントをその申請がもう受け付けないことを、頭で言う。打った値は残る。

ページの言語での断りの文（`Refusal.In`。日本語のページでは日本語の文で、無ければ英語の文。ほかのページでは英語の文）と problem は、ページの頭の「申請を管理している人向けの詳細」の下に畳んで見せる。

答えは、読んだ結果の `Problem` になる。`Place` は部品（`trip_to`、`items.1.price`、`comment`。ページの頭なら空）、`Code` はその部品のどの検査の文言で言うか（どの検査でもなければ `refused` か `invalid`）、`Words` はページがそこで言う文である。経費の申請の断り

```json
{"refused": "form", "text": "`0JPY` is outside the range of `items[1].price` (`>=1JPY <=1_000_000JPY`)", "at": "items[1].price"}
{"refused": "form", "text": "the `amount` the form works out is outside its range (`>=1JPY <=10_000_000JPY`)", "at": "amount"}
```

は、次のように読む。

```go
Problem{Place: "items.1.price", Code: "refused", Words: "Check Price (Items): the request does not take this value."}
Problem{Place: "amount", Code: "amount.worked", Words: "The Amount the form works out is outside its range (from 1 JPY to 10,000,000 JPY). Change Price (Items)."}
```

日本語のページでは、`明細の金額の値を受け付けられませんでした。確かめてください。` と `計算した合計が、範囲（1円から10,000,000円まで）の外です。明細の金額を直してください。` になる。計算した値は打てないので、その断りは、値を計算するのに読むフィールド（説明の `reads`）をラベルで挙げ、そのどれかを直すように言う。`Change Quantity or Unit price (Lines).`、`明細の数量か単価を直してください。` のように、一つの明細のフィールドは明細を一度だけ言う。この文はページの頭の一覧の行で言う。値の所では、その検査を通らなかった物として見せ、文は A2UI の画面の検査の文（フィールドを挙げない）のままである。読んだ結果が持つ答えは一つで、あとの答えは前の答えが言ったことを置き換える。

### 4.5 キー

キーは `screens` が、面、ボタン、本文と、チケットへの操作なら時刻から作る。時刻はページを見せた時刻（`_at`）なので、同じページを二度送っても（ダブルクリックや送り直し）一つの操作になる。ファイルは一度だけ預かり（4.3）、変えた物は、ページが見せたフォームと比べて読む（4.1）。スクリプトも、送ったフォームを 3 秒のあいだは送り直さない（6 章）。もう一度見せるページは新しい `Now` で作り、新しい申請の申請書は新しい面で作る（`screens` が求めるとおり）。断られた人が、同じ値をもう一度送れるようにするためである。

## 5. 数

数のフィールドは、送るときは単位の刻みの整数を持つ。人が打ち、読むのは、人が数える単位での量である。

| 型 | 一刻み | 打つ形と見せる形 | 送る値が 125 のとき |
|---|---|---|---|
| `number` | 1 | `125` | `125` |
| `money[JPY]`、`money[円]` | 1 円 | `125` と `JPY`（日本語では `円`） | `125 JPY`、`125円` |
| `money[銭]` | 1/100 円 | `1.25` と `JPY`（日本語では `円`） | `1.25 JPY`、`1.25円` |
| `money[USD]` | 1 ドル | `125` と `USD` | `125 USD` |
| `money[USDc]` | 1/100 ドル | `1.25` と `USD` | `1.25 USD` |
| `rate[step 0.1%]` | 0.1% | `12.5` と `%` | `12.5%` |
| `rate[step 0.25%]` | 0.25% | `31.25` と `%` | `31.25%` |
| `rate[step 2.5%]` | 2.5% | `312.5` と `%` | `312.5%` |
| `rate[step 1%]`（ソースが刻みを書かない率） | 1% | `125` と `%` | `125%` |
| `mass[kg]` とほかの量 | その単位の 1 | `125` と `kg` | `125 kg`、`125kg` |

数は、刻みが持つ小数の桁を、0 のときも見せる。`rate[step 0.1%]` で 0 から 1000 刻みの範囲は `0.0%から100.0%まで` である。入力の中の値はカンマ無しで書き、見せる値と検査の範囲は、整数の部分が 5 桁以上なら区切る（`9999`、`10,000`）。

A2UI の画面も、数を同じに書く。率と、1/100 で数える金額と、量は、カタログの `formatSteps` で見せ（整数だけで計算し、刻みの小数の桁を 0 のときも書き、整数の部分が 5 桁以上なら区切り、後ろに単位を付ける）、同じ `decimals`・`step`・`unit` の `AmountField` で尋ねる（ringi の DESIGN 13.1〜13.3）。`TestStepsAsTheScreensShowThem` が、率とセントを生成した画面で、ページを両方に突き合わせる。

読むときは、符号、小数点、区切りのカンマの付いた数字（全角の数字と符号も）と、その後ろに、ページが見せるとおりの単位（円なら `¥` と `円` も）を受け、`math/big` で整数を正確に作る。浮動小数点はどこにも使わない。刻みの整数倍でない値は、丸めずに、どの刻みで書くかを言って断る。刻みが 0.1% のところに 12.34 と打った人が何を意味したかは、ページには推し量れないからである。ブラウザが正確に持てない整数（2^53 − 1 を越える物）は、A2UI の画面と同じく範囲の外とする。スクリプトも `BigInt` で同じに読む。

## 6. スクリプト

`page.js` は ES モジュールである。`functions.js` を読み込み、ページのフォームごとに、部品から A2UI の画面と同じ形でフォームの値を作り（選択は一つだけの配列、数は刻みの整数、明細は並び。承認カードでは、承認者の直しのあとのチケットのフォーム、`<種類>.edited`）、値が変わるたびに次をする。

- 条件で見せるフィールドは、`<種類>.shown_<フィールド>` が成り立つあいだだけ見せ、隠れているあいだは disabled にする。条件で必須になるフィールドは、`data-required-when` が名指す関数が成り立つあいだだけ必須の印を付ける。
- 計算する数（`<種類>.<フィールド>`）を、単位を付けて見せる。
- 人が変えた部品ごとに、通らない検査を言う（`<種類>.check`、数と日の読み方、コメント）。
- ボタンが押されたら、そのボタンの検査（フォームの検査、直しの検査、あるいはコメントだけ、足す承認者、引き継ぎの検査。理由を求める操作なら `commentGiven`）をし、通らない物があれば送らずに、フォームの頭に一覧を出す。一覧のどれも、その部品へのリンクである。

行は送らずに足し、消す。送ったフォームは、3 秒のあいだ（`SENT_FOR`）送り直さないので、ボタンを二度押しても申請は一つである。本人が止めた送信（Esc や、ブラウザの読み込みを止めるボタン）には答えが来ないので、その 3 秒のあとはもう一度送れる。何も変えていなければ、サーバーは一度目と同じに答える（4.5）。ブラウザがキャッシュから戻したページ（戻るボタン）は、すぐにもう一度送れ、サーバーは同じに答える。入力メソッドの変換を終える Enter（`isComposing`、または変換を先に終えるブラウザのキーコード 229）は、入力メソッドの物である。`functions.js` が読み込めないときや、ブラウザがモジュールを動かさないときは、スクリプトの無いページと同じに動く。

## 8. ここでしないこと

HTTP のハンドラー、サイトをまたぐ投稿を防ぐこと（`http.CrossOriginProtection`、またはサーバーが作って `_csrf` で確かめるトークン）、セッション、ログインとログアウト、ファイルの保管はサーバーの受け持ちである。選ぶ部品に並べる人、チーム、マスタの行を決めるのも、ホームに並べる種類、ページを見せる言語、答えごとのステータスを決めるのも、サーバーである。
