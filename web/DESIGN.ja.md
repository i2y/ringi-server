# ページ、画面、添付ファイルを HTTP で出す（`web`）

英語：[DESIGN.md](DESIGN.md)。

このパッケージは、サーバー（`server.Server`）を一つの `http.Handler` の後ろに置き、人が申請を出し、承認し、自分の申請を見る素の HTML のページ（9 節）と、申請の種類の画面（ringi の DESIGN 13 章の A2UI の画面）を出し、ボタンの操作を受け、ritsu のカタログと関数を配り、添付ファイルを預かって配ります。どのリクエストも同じ守りを通ります。だれが送ったか、別のサイトから送られたリクエストへの守り、大きさの上限、ブラウザにしてよいことを絞るヘッダーです。

画面はパッケージ `screens` の物、ページはパッケージ `screens/page` の物です。このパッケージは、サーバーのデータで画面とページを埋め、その操作を本人として実行するだけで（`Server.Do`）、申請の種類ごとのコードを持ちません。画面のボタンもページのフォームも同じ API の操作になるので、画面、ページ、API が食い違うことはありません。

## 1. 使い方

```go
srv, err := server.New(cfg) // cfg.Files に添付の置き場を渡す（6 節）
h, err := web.New(srv, web.Config{})
http.ListenAndServe(addr, h)
```

`web.New` は、サーバーが受け持つパッケージごとに画面とページを読み込みます（パッケージのファイル `types/`、`a2ui/`、`openapi.json` を `screens.Load` で読み、その上に `page.New` でページを作る）。読み込めないパッケージがあれば、エラーを返します。一つのパッケージの画面とページは、いくつのハンドラーが使っても一度だけ読み、パッケージが使われなくなれば手放します。ハンドラーは下の表のルートに答え、それ以外のリクエストはサーバーの API に渡します。

```go
type Config struct {
	MaxFile        int64    // 添付の大きさの上限（バイト。0 なら 10 MiB）
	FileTypes      []string // 添付として受け付けるメディアタイプ（nil なら 6.2 節）
	Inline         []string // ブラウザで開くメディアタイプ（nil なら 6.3 節）
	TrustedOrigins []string // 自分のオリジンのほかに、状態を変えるリクエストを受け付けるオリジン
	Logger         *slog.Logger

	// ページのためのログインのフック（3.1 節）
	Require  func(http.Handler) http.Handler // ページの各ルートを包む
	LoginURL func(returnTo string) string    // 「ログインしていません」の知らせのリンク
	SignOut  string                          // 帯のボタンがログアウトのために送る先のパス
}
```

ボタンの操作の本文の上限は、API の本文と同じく、サーバーの `Config.MaxBody` です。ページから送るフォームの上限は、`MaxBody` と、10 個までのファイルそれぞれの `Config.MaxFile` です（9.3 節）。

画面の言語は `?lang=`（`en`、`ja`）で選びます。無ければ、`Accept-Language` のうち、その種類が書かれている最初の言語、それも無ければ、組織のデータがログインしている人に与える言語（ヘッダーが `q=0` で断っていなければ）、それも無ければ、種類の説明を書いた言語です（`server.LanguageChoice`。ページと同じ選び方）。その種類が書かれていない言語は 404 です。ページの言語の決め方は別です（9.4 節）。

### 2.1 画面のルートの答え

A2UI 1.0 のメッセージを、レンダラが受け取る順（`createSurface`、`updateDataModel`、`updateComponents`）に並べた JSON の配列です。`Content-Type: application/json`、`Cache-Control: no-store`。配列はパッケージ `screens` が埋めたとおりで、このパッケージはメッセージを書き換えません。A2UI 1.0 より前の名前を読むレンダラには、`?names=old` で `Screen.WithOldNames` の形を返します（ringi の DESIGN 13.5）。

| 画面 | 埋める物 |
|---|---|
| 新しい申請のフォーム | `Form`：今日有効なバージョン。本人が自分の申請か、だれかの代わりの申請を出せるときは `Can` に `submit`。`MaySubmit` と `SubmitFor`（4 節）。サーフェスは毎回、新しいランダムな物。`Serving`（下） |
| 承認カード | `Card`：`get_ticket` が返すチケット。`Can` はゲートに聞く（4 節）。`Serving` |
| チケットのフォーム | チケットを入れた `Form`。`Can` は `resubmit` と `discard`。`Serving` |
| 履歴 | `History`：チケットと、サーバーが記録した時刻つきの履歴の行 |
| 待っている物の一覧 | `List`（画面 `list`）：その種類のチケットのうち、本人を待っている物（`Server.Waiting`。`list_waiting` が返す物と同じ）。画面はその種類の最新のバージョンの物 |
| 本人の申請の一覧 | `Mine`（画面 `mine`）：その種類の本人の申請（`Server.Mine`。`list_mine` が返す物と同じ）。画面はその種類の最新のバージョンの物 |
| offered | `Offered`（画面 `offered`）：有効なバージョンが今は無く、あとのバージョンが始まる日から申請を出せる種類の画面（`Server.Offered`）。`/from` にその日、`/home` に言語を保ったホーム（`keepLang(r, PagesPath)`） |

チケットの画面は、チケットが持っているバージョンの画面で埋めます。本人が見られないチケットは、API と同じく 404 です（本体の DESIGN 10.3）。新しい申請は、その種類に有効なバージョンが無いとき、または本人が自分の申請もだれの代わりの申請も出せないとき、フォームを見せられません。あとのバージョンが始まる日から出せる人（`Server.Offered`。本体の DESIGN 10.1）には、その種類の `offered` の画面を、出せる日とホームへ戻る先を埋めて、専用のサーフェスで返します。その種類の最新のパッケージが画面を持つときです。その画面が無いパッケージ（約束の同じ版で、画面が加わる前に生成された物）には、前と同じく、API の申請と同じ形で 404 で日付を言います。`{"error": "This request may be made from 2027-04-01.", "from": "2027-04-01"}` の形で、`error` は画面の言語の文です（`screens.OfferedWords`。ページとエージェントのツールも同じ文を言います）。ほかの人と、始まるバージョンが無いときは `{"error": "no such kind of request"}` です。

フォームと承認カードには、ハンドラーが決める物（`screens.Serving`。ringi の DESIGN 13.8 の置き場）も入れます。入れるのは、画面のテンプレートが持つ置き場だけです。

- `/find`：選ぶ部品が値を探すアドレス。`web.FindPath`（`/a2ui/find`。5.1）。
- `/upload`：`FileAttachment` がファイルを送るアドレス。`web.UploadPath`（`/files`。6.2 節）。サーバーがファイルを預からない（`server.Config.Files` が無い）ときは null のままです。
- `/refused`：画面を見せるときは `{"text": null, "field": null, "comment": false}` です。ボタンが送った操作が断られると、その文と、フィールドかコメントの断りかが入ります（2.2 節）。

承認カードの `/ticket` には、API のチケットのキーを同じ名前で入れます。`requester` と `made_by` もその中にあり、カードは承認者と同じく、`/people` でその名前を引きます。待っている物の一覧の行は、チケットの `id`、`status`、`stage`、`requester`、`form` を持ちます。本人の申請の一覧の行は、`requester` の代わりに `made_by` を持ちます。

二つの一覧は、新しい順に 1 ページずつ読みます。1 ページは `?limit=` 件までで、1 から 100（`server.MaxPage`）、無ければ 50（`server.DefaultPage`）です。ほかの値は、API の一覧と同じ文の 400（`limit: a whole number from 1 to 100 is expected, not "0"`）です。`?before=` は前のページの最後のチケットで、その次から返します（本人を待っていないチケットや、本人の物でないチケットなら、空のページです）。待っている物は待ち始めた時刻（待っているステップが始まった時刻か、申請者に戻った時刻）が新しい順、本人の申請は出した時刻が新しい順で、同じ時刻なら ID の大きいチケットが先です。ストアからも 1 ページずつ読みます（`server.WaitingQuery`、`server.MineQuery`）。続きがあるかを知るために、ページより 1 件多く読みます。続きがあれば一覧の `/more` は `true`、最後のページなら、`limit` の数まで埋まっていても `false` です。一覧のボタン `more`（`/more` が真のときに見える）は、一覧の操作（`list_waiting`、または一覧の種類を付けた `list_mine`）を、ページの最後のチケットを `before` にして送ります（2.2 節）。

### 2.2 ボタンの操作

本文は、ボタンが押されたときにレンダラが送るメッセージ（`{"version": "1.0", "action": {…}}`）で、`application/json`（か `application/a2ui+json`）です。ほかのタイプは 415 です。ハンドラーはメッセージを読み（`screens.ParseAction`）、サーフェスの種類の画面（チケットへの操作なら、チケットのバージョンの画面）を選び、操作にし（`Set.Operation`。冪等キーもここで作る）、本人として実行します（`Server.Do`。監査ログのために `Via: "screens"` を付ける）。読めないメッセージ、どの画面の物でもないメッセージ、そのイベントを送らないボタンのメッセージは 400 です。

答えは JSON のオブジェクトで、HTTP のステータスは API の答えと同じです。

```json
{"outcome": "ok", "ticket": "T-1", "messages": [ … ]}
{"outcome": "refused", "refused": "stale", "text": "…", "words": "…", "messages": [ … ]}
{"outcome": "invalid", "problem": "form.receipt: no such file", "messages": [ … ]}
{"outcome": "limited", "problem": "…", "words": "…", "retry_after": 7, "messages": [ … ]}
```

- **ok**（200）：操作のあとの画面です。ボタンがあったサーフェスを消し（`deleteSurface`）、チケットの承認カードを送ります。カードでの操作のあとは、同じサーフェスで埋め直したカード、フォームのボタンのあとは、チケットの ID のサーフェスのカード（新しい申請なら、新しいチケットの物）です。一覧の行（`get_ticket`）は、そのチケットのカードを送り、何も消しません。一覧のボタン `more`（`list_waiting`、`list_mine`）は、一覧のサーフェスを消し、同じサーフェスで次のページを送ります。`before` のあとのチケットを 50 件まで、そのページの `/more` と一緒に送ります。一覧の種類と違う `kind` は 400 です（`kind: the list is of expense, not leave`）。
- **refused**（409）：`refused` は API の拒否の種類、`text` は API の文を画面の言語にした物です（`ja` なら、API が返していれば `text_ja`、無ければ `text`。ringi の DESIGN 12.4）。`words` は、本人に見せる一文で、画面の言語で、拒否の種類だけから作ります。`text` からは作りません。`text` は、イベント、フィールド、種類の行を、種類が書いたままの名前で言うからです（`` `self approval not allowed` ``）。文は、パッケージ `screens` の一つの表（`screens.RefusalWords`）の物で、ページも同じ文を出します。チケットのカードやフォームが今のチケットと合わなくなっている拒否（`stale`：チケットが先に進んだ。`state`：今のチケットにはそのイベントが当てはまらない。`person`：本人は今それができない）のあとは、サーフェスを消し、今のチケットで埋め直し、`/refused` に断りを入れ、コメントを戻して送ります。これで、見えるボタンは押せる物だけになります。本人がもうチケットを見られないときは、消すだけです。ほかの拒否（`form`、`comment`、`limit`、`clock` など）と、新しい申請のフォームでの拒否のあとは、画面を送り直しません。送るのは、サーフェスの `/refused` に断りを入れるメッセージ一つ（`Set.Refused`。`updateDataModel`）です。`text` は画面の言語の文です。`field` は、`form` の断りが指す場所（`at`）の最初の名前（`items[1].price` なら `items`、`lines[0].subtotal` なら `lines`）で、場所を指さない断りなら null です。`comment` は、種類が `comment` の断りなら、どの操作でも真、ほかは偽です。本人が入れた値は残り、画面は断りを、そのフィールドの横か、コメントの下か、画面の頭に見せます（ringi の DESIGN 13.1、13.8）。
- **invalid**（400）：API と同じ問題の文です（読めない本文、本人が指定できない添付など）。画面は送り直しません。送るのは、前に見せた断りを画面から消すメッセージ一つ（`/refused` を null に、`comment` を偽に戻す）で、本人が入れた値は残ります。ハンドラー自身が断るメッセージ（上）にも同じ形で答え、メッセージは空です。
- **limited**（429）：サーバーがいまは受け付けないコメントです（コアの DESIGN 7.4）。`words` は、そのことを画面の言語で言う一文です（`screens.LimitedWords`。ページも同じ文を出します）。`retry_after` とヘッダーの `Retry-After` は待つ秒数で、待っても変わらないとき（チケットがその人のコメントをこれ以上受け付けない）は付けません。画面は送り直しません。invalid と同じく、前に見せた断りを消すメッセージを一つ送り、本人が入れた値は残ります。
- チケットが無いか、本人が見られないときは 404。だれも送っていないときは 401。今は有効なバージョンが無い種類のフォームへのアクション（管理する人が止める前に読んだフォーム）には、今のフォームと同じに答えます（2.1 節）。その日から出せる人には `offered` の画面か、日付の 404 です。サーバーが受け持たない種類の面へのアクションも同じです。

### 2.3 カタログと関数

パッケージの画面は、それぞれ自分のカタログと関数を持ちます（`Set.Asset`）。ritsu がパッケージの種類と一緒に生成した物で、画面を描く部品と、フォームがする確かめです。種類のある版の画面とページは、その版が入っているパッケージの物を使います。いちばん新しいパッケージの物は `/a2ui/catalog.json` と `/a2ui/functions.js` に、そのページのファイルは `/pages/assets/` にあります。パッケージが一つだけのサーバーが、そのパッケージの物を出すアドレスと同じです。ほかのパッケージの物は、それぞれ自分のアドレス `/a2ui/{files}/` と `/pages/assets/{files}/` にあります。`{files}` は、その `catalog.json` と `functions.js` の SHA-256 の、16 進の最初の 16 桁です。そのパッケージの種類のページは、ここからスクリプトを読み込みます（その `page.js` は、横の `functions.js` を import します）。どのファイルも、その `Content-Type`、強い `ETag`、`Cache-Control: no-cache` を付けて出します。`If-None-Match` がその ETag なら、本文なしの 304 です。だれのデータも持たないので、人がいなくても答えます。ほかの `{files}` や、ほかの名前は 404 です。

画面の答えは、その画面を描くカタログを `Link` ヘッダーで言います（`</a2ui/…/catalog.json>; rel="describedby"; type="application/json"`）。その横の `functions.js` で、画面の確かめを動かします。レンダラは一つの ID にカタログを一つしか持たないので、二つのパッケージの画面が一つのカタログの ID を別々のファイルに付けると、一方のパッケージの画面が、もう一方の部品で描かれてしまいます。`New` はそれを断ります（`*CatalogConflict`）。エラーは、二つのパッケージ（`Config.Packages` の順に 1 から数える）とその種類、ID、すること（どちらかを、自分のカタログの ID で作り直す。`ritsu gen --catalog`）を、英語と日本語で言います（`CatalogConflict.In`）。画面が一つの ID を同じファイルに付けるパッケージは受け付けます。

## 3. 守り

API も含め、どのルートにも次の守りがあります。

- **だれが送ったか。** リクエストごとに、サーバーの `Authenticator` に聞きます（`Server.Authenticate`）。人がいなければ 401 です（ページでは知らせで伝える。9.5 節）。人を求めないのは、カタログ、関数、ページのファイル、ブラウザをホームへ送る `/` だけです。
- **別のサイトから送られたリクエスト。** いちばん前に `http.CrossOriginProtection` を置きます。ブラウザが別のオリジンから送った POST（GET、HEAD、OPTIONS のほかのメソッド）は、`Sec-Fetch-Site` か、ホストがリクエストのホストと違う `Origin` で見分け、本文を読む前に 403 にします。答えは JSON のエラーで、ページのパスなら知らせです。`Config.TrustedOrigins` は、受け付けるオリジンを足します（別のオリジンで画面を描くホスト）。ブラウザからでないリクエスト（`Sec-Fetch-Site` も `Origin` も無い物）は、API のクライアントと同じく通ります。ボタンの操作は JSON でなければならず、別のサイトのフォームは、先に確かめを取らなければ JSON を送れません。ページのフォームには専用のトークンが要りません。別のサイトからの送信はこの守りが断るので、ページが持てる `_csrf` のフィールドは空のままです。
- **大きさ。** API の本文とボタンの操作の本文は、サーバーの `MaxBody`（無ければ 1 MiB）までで、超えれば 413 です。アップロードは `Config.MaxFile`（無ければ 10 MiB）までで、超えれば、その先を読まずに 413 です。ページの送信は 9.3 節です。
- **ヘッダー**。どの答えにも付けます。

| ヘッダー | 値 |
|---|---|
| `Content-Security-Policy` | `default-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`（保存させるダウンロードには `sandbox` を足す。ページは下の `web.PagePolicy`） |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `same-origin` |
| `X-Frame-Options` | `DENY` |
| `Cache-Control` | `no-store`（カタログ、関数、ページのファイルは `no-cache`） |

インラインのスクリプトとスタイルは、どの答えでも許しません。ページは、スタイルシートとスクリプトをサーバーから読み込み、`web.PagePolicy`（`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`）の下で動きます。

### 3.1 ログイン

だれが送ったかは、サーバーの `Authenticator` が決めます。どの `server.Authenticator` も、同じ所（サーバーの `Config.Authenticator`）に入れます。ページも画面もファイルも API も、これに聞きます（`Server.Authenticate`）。人のいないリクエスト（セッションが無い、または終わった）には `server.ErrNoPerson` を返し、これは 401 になります。ほかのエラーはサーバーの失敗で、500 を返してログに書きます。

このパッケージには、人をログインさせるプロキシの後ろに置くサーバー向けの物（`web.ProxyHeader`）があります。プロキシが付けるヘッダー（人と、そのロール）を信じるのは、プロキシだけが知っている秘密を専用のヘッダーに持つリクエストだけで、秘密は一定の時間で比べます。秘密が無いか違うリクエストは、人を名乗っていても、人がいない扱い（401）です。人のヘッダーだけなら、だれでも送れるからです。設定の誤りは `ProxyHeader.Check` が言い、`server.New` がそれを聞きます（`server.Checker`）。誤った設定のサーバーは、リクエストを受ける前に、何が違うかを言って止まります。誤りは、秘密が無いか 32 文字より短い（`web.ErrShortSecret`）、秘密の端に空白がある・制御文字や ASCII の外の文字がある（ヘッダーはそのままでは運ばないので、どのリクエストも合わなくなる）、ヘッダーの名前が名前の形でない、三つのヘッダーのうち二つが同じ名前、です。

```go
auth := web.ProxyHeader{Secret: os.Getenv("RINGI_PROXY_SECRET")} // X-Ringi-Proxy-Secret、X-Ringi-Person、X-Ringi-Roles
```

プロキシは、渡すリクエストのどれにも、ヘッダーについて三つのことをします。

1. クライアントが送った三つのヘッダー（`X-Ringi-Proxy-Secret`、`X-Ringi-Person`、`X-Ringi-Roles`、または代わりに渡した名前）を、大文字と小文字の違いにかかわらず消す。
2. 三つを一つずつ付ける。秘密、人、その人のロール（コンマで区切る）である。
3. ロールの無い人にも、ロールのヘッダーを空で付ける。

三つのどれかが二つ以上あるリクエストと、ロールのヘッダーが無いリクエストは、人がいない扱い（401）です。クライアントのヘッダーを置き換えずに足すプロキシは、これで止まります。クライアントの `X-Ringi-Roles: workflow_admin` とプロキシの `X-Ringi-Roles: staff` が二つ届くからです。ロールの無い人にロールのヘッダーを付けないプロキシなら、クライアントのヘッダーだけがその場所に残るところでした。クライアントの値と自分の値を一行につなぐプロキシ（`workflow_admin, staff`）は止まりません。その人の二つのロールとして読めるからです。これを防ぐのは、上の 1 だけです。

セッションを持つログイン（パッケージ `oidc`。組織の OpenID Connect のプロバイダーでログインする）は、サーバーの `Authenticator` になり、自分のルートをこのハンドラーに足し、ページに三つのフックを渡します。

```go
srv, err := server.New(server.Config{…, Authenticator: signIn})
h, err := web.New(srv, web.Config{Require: signIn.Require, LoginURL: signIn.LoginURL, SignOut: "/logout"})
signIn.Mount(h) // GET /login、GET /login/callback、POST /logout を Handler.Handle で足す
```

- `Config.Require` は、ページの各ルートを包みます。セッションのないままページを開いたブラウザは、ログインへ進み、あとで戻ります。渡さないときは、人のいないページの要求には「ログインしていません」の知らせ（401）を返します。
- `Config.LoginURL` は、その知らせに、ページへ戻るログインのリンクを付けます。セッションなしでフォームを送ったときや、入力しているあいだにセッションが終わったときのためです。
- `Config.SignOut` は、帯のボタン（9.5 節）が送る先のパスです。`""` ならボタンを出しません。
- `Handler.Handle` で足したルートは、人を自分で調べます（`Handler.Person`）。ログインのルートは、まだセッションの無い人のための物だからです。答えには、ルートが書く前に 3 章のヘッダーが付いています。HTML のページを返すルートは、自分の `Content-Security-Policy`（`web.PagePolicy`）を付けます。パターンは 2 章のルートと重ねられません（重なると `ServeMux` が panic します）。
- クロスサイトのリクエストへの守りがあるので、クッキーのセッションを POST で送っても安全です。ほかのサイトからの POST は、ログアウトも含め、どのルートより先に断ります。認可コードフローのコールバックは GET なので、守りを通ります。答えを POST で返すプロバイダー（`response_mode=form_post`）は、自分のオリジンから POST を送るので、そのオリジンを `Config.TrustedOrigins` に足します。

フレームワークには、手元のコンピューターでページを試すためのログインがあります（パッケージ `devlogin`）。そのページに組織の人が並び、選んだ人としてページを使います。選ぶ部品が並べる数（`web.PicksListed`、1,000 人）より人の多い組織では、人を並べず、選ぶ部品と同じように、名前の一部か ID で、API の `find_people` と同じに探します（`server.FindQuery.Answer`。`page.FindShown` の 20 人まで）。スクリプトは要りません。名前の無い人は ID だけで並びます。今日有効な組織の版が無ければ、だれもいないと言い、だれも入れません。本人の確認をしないので、ループバックのアドレスに送られ、プロキシを通っていない（`X-Forwarded-For` や `Forwarded` など、プロキシが足すヘッダーが無い）リクエストにだけ答えます。サーバーのコマンドも、ループバックのアドレスで待ち受けるときにだけ使い（パッケージ `serve` の `-dev-login`。例のサーバーもこれを受け付けます）、人に使ってもらうサーバーの設定と一緒には使いません（根の README の「ログイン」）。

## 4. `Can` と、だれが申請を出せるか

画面とページは、ゲートがそのイベントを許すときにボタンを出します（`/can`）。ハンドラーはサーバーに聞きます。

- `Server.Can(ctx, person, ticket, events)` は、画面のイベント（`Set.Actions`）のうち、今のチケットで、ゲートが本人に許す物を返します。操作のときと同じく、各イベントのアクション（本体の DESIGN 8。`edit` は `approve`、`discard` は `withdraw` など）を、同じ問いでゲートに聞きます。本人が見られないチケットは `server.ErrNotFound` です。
- `Server.Submitting(ctx, person, kind)` は、新しい申請について、今日有効なバージョン、本人が自分の申請を出せるか（`list_requests` と同じ決め方。本体の DESIGN 10.1）、本人が代わりに出せる人を返します。代わりに出せる人は、その日、その種類で本人が `submit` の代理になっている人で、一人ずつ、その人自身と同じように、種類の `start` とゲートに聞きます。

ボタンを出すか隠すかだけで、操作を実行するときには、あらためてゲートに聞きます。

## 5. `Lookup`

画面の名前の引き当て（`screens.Lookup`）は、一つの型 `web.Lookup` が、A2UI の画面にもページにも答えます。人とチケットごとに作ります（`Handler.Lookup`）。

- **人とチーム**：今日有効な組織のバージョンでの名前（`Server.Names`）を、画面の言語で。`ja` ならデータに `name_ja` があればそれ、無ければ `name`。
- **マスタの行**：今日選べる行（`Server.MasterRows`）を、マスタの名前の列で。名前の列は、種類の説明が行の名前に使う列（`name_field`。ringi の DESIGN 12.2。`MasterLayout.NameField`）で、どの言語でも同じです。名前の列の無いマスタは行に名前を付けず、画面はキーをそのまま見せます。
- **ファイル**：ハンドラーがそのファイルを出すアドレス。チケットに載っているファイルは `/tickets/{ticket}/files/{id}`、本人がアップロードして、まだチケットに載っていないファイルは `/files/{id}`。ほかの ID にはアドレスを返さず、画面は ID をそのまま見せます。

ページは、フィールドが選ぶ値の候補も出します（`page.Picks`）。今日有効な版の人とチーム（`Server.People`、`Server.Teams`）と、種類のフィールドが選ぶマスタごとの、今日選べる行です。どれも、ページの言語の名前に ID かキーを添えて見せます（「Sales staff 1 (e1201)」、「営業担当 1（e1201）」）。1,000 件（`web.PicksListed`）を超える部品は並べず、名前で探します（`page.Picks.Find`。5.1 と同じ探し方）。API と同じ ID やキーを打ち込むこともできます。スクリプトがあるときと無いときの部品の動きは、`screens/page` の DESIGN の 3.1.1 にあります。

### 5.1 名前で値を探す

`GET /a2ui/find/people`、`GET /a2ui/find/teams`、`GET /a2ui/find/masters/{file}/{master}` は、選ぶ部品が `?q=` の言葉で探す値を返します。今日有効な組織の版の人かチーム、またはマスタの今日選べる行です。答え方は API の探す操作（`find_people`、`find_teams`、`find_master_<file>_<master>`。ringi の DESIGN 13.2）と同じで、API と同じ関数（`Server.FindValues`）で答えます。引数を読む順も、見つかる値とその順も同じで、200 と 400 の本文はバイトまで API と同じです。レンダラの `PersonPicker`（`of` は `person` か `team`）と `MasterPicker`（`master` は `masters/` のあとのパス）は、画面の `/find` にあるアドレスの下で探します（ringi の DESIGN 13.2、13.8）。ハンドラーは、埋めるフォームとカードのどれにも、そこに `web.FindPath`（`/a2ui/find`）を入れます（2.1 節）。ページのスクリプトも、画面の `/find` から同じアドレスを読んで探します。ページの候補と同じく、ログインしている人に答えます（いなければ 401）。答えるのは ID かキーと名前で、メールアドレスは返しません（アドレスは `get_organization` が、その版の人にだけ返します）。

```
GET /a2ui/find/people?q=staff+3&lang=en

{"found":[{"value":"e1203","name":"Sales staff 3","label":"Sales staff 3 (e1203)"}],"more":false}
```

- **`q`** は探す言葉で、UTF-8 で 200 文字（コードポイント）までです。どの言葉も、ID かキー、またはどちらかの言語の名前（人とチームは `name` と `name_ja`、マスタの行は、`Lookup` が付ける一つの名前（名前の列））に含まれる値が見つかります。言葉は Unicode の White_Space の文字で区切ります。言葉が無ければ、全部の値が見つかります。
- **比べ方**（`server.Fold`）：Unicode の互換の形（NFKC。全角の英字と数字は ASCII に、半角のカタカナは全角に）にし、White_Space の文字を除き、ひらがなをカタカナにし、一字ずつ小文字にして比べます（語末の「ς」は「σ」。「İ」は「i」で、「ß」は「ss」にしません）。「佐藤一郎」で「佐藤 一郎」が、「さとう」と「ｻﾄｳ」で「サトウ」が、「SALES」で「Sales」が見つかります。
- **近い順**：言葉がそのまま値である物（打ったまま、次に比べ方を当てて）、言葉が名前の一つである物、ID かキーか名前が最初の言葉で始まる物、残りの順です。同じ近さの値は、ID かキーの順（コードポイントの順）です。
- **`limit`** は 1 から 100 で、無ければ 20 です。`more` は、返した数より多くの値が言葉を含むかです。
- **`lang`**（`en`、`ja`）は、`name` と `label`（ページと同じく、名前に ID かキーを添えた物）の言語です。無ければ `Accept-Language` のうちの最初のどちらか、それも無ければ `en` です。名前の無い値は `name` が空です。名前が無いか、名前が ID かキーと同じ値は、`label` が ID かキーだけです。
- **`on`** はマスタの行だけの引数で、行を選べる日（`YYYY-MM-DD`）です。無ければ今日です。
- 引数は `q`、`limit`、`lang`、`on` の順に読み、受け付けない最初の物を 400 で言います（`limit: a whole number from 1 to 100 is expected, not "0"`）。空で渡した引数は、渡さなかったのと同じです。
- ほかの物を探すアドレスと、どの種類も選ばないマスタ（API にその行を探す操作が無い）は、引数を読む前に 404（`no such path`）です。人とチームは、今日有効な組織のバージョンにいない人と、有効なバージョンが無いあいだは、API と同じ文で 404 です（本体の DESIGN 9.4）。マスタの行は、ログインしている人ならだれでも探せます。

ページも同じに探します。候補を並べない部品は、API の探す操作が選ぶ値（`Server.FindChoices`）から `server.Find` で探し、例のログインは `server.FindQuery.Answer` で探します（3.1 節）。値を持つ部品は、その下に名前を言い、名前が値と同じなら言いません。探す操作が受け付けるより長い言葉は、そもそも送りません。ページのスクリプトが、400 が持つのと同じ文で、そのことを自分で言います（ページの DESIGN 3.1.1）。

## 6. 添付ファイル

### 6.1 置き場

`server.Files` が、だれがいつアップロードしたか（`FileInfo.By`、`FileInfo.At`）と一緒に預かります。フレームワークには二つの置き場があります。

- **ディスク**：`web.NewDiskFiles(dir)`。ファイルは `<dir>/<id の頭の 2 文字>/<id>`、記録は同じ場所の `<id>.json`。どちらも一時ファイルに書いてから名前を変えて置きます。
- **PostgreSQL**：`(*postgres.Store).Files()`。表 `files` を一つ（8 節）。中身は `bytea` の列に入れます。

ID は 16 バイトの乱数を 32 文字の小文字の 16 進で書いた物です。それ以外の ID は探しません。

### 6.2 アップロード

`POST /files`。`multipart/form-data` で、パート `file` を一つ。ハンドラーはストリームとして読み、`Config.MaxFile` を超えれば 413 で、何も残しません。パートのメディアタイプは `Config.FileTypes` のどれかでなければならず、違えば 415 です。指定が無いときは、PDF、PNG、JPEG、GIF、WebP、プレーンテキスト、CSV、文書・表計算・プレゼンテーションの形式（OOXML と OpenDocument）を受け付けます。タイプの引数は `charset`（英字・数字と `-_.:+()` の 40 字までの名前）だけを残し、ほかは落とします。

ブラウザで開くタイプ（PDF と、PNG、JPEG、GIF、WebP の画像）は、ファイルの頭がそのタイプの物でなければ 415（`the file is not of the type it is sent as`）です。PDF は最初の 1,024 バイトに `%PDF-` があるか（PDF のビューアーが探す所）、画像は形式ごとの頭のバイトで見ます。`Config.Inline` に入れられるのは、このタイプだけです（`New` がほかを断ります）。ブラウザが見せる物は、タイプの言うとおりの物になります。

名前は、パートのファイル名から、ディレクトリと、制御文字と、書式文字（Unicode の Cf。文字の並ぶ向きを変える文字と、幅の無い空白。`fdp.exe` の前に U+202E を置いた名前は、`exe.pdf` で終わるように見えます）を除いた物で、255 バイトまでです。名前の拡張子がタイプの物でなければ、タイプの拡張子を足します（PDF として送った `invoice.exe` は `invoice.exe.pdf` になります）。保存したコンピューターが、サーバーが受け取ったとおりの種類として開くためです。答えは 201 です。

```json
{"id": "9f2c…", "name": "receipt.pdf", "content_type": "application/pdf", "size": 48213, "url": "/files/9f2c…"}
```

ハンドラーは、ファイルを `server.Server.Upload` で預けます。サーバーはそれを、まだどのチケットも持たない、その人のアップロードとして記録します（コアの DESIGN の「差し替える物」の Files）。そういうアップロードを `server.Config.UploadsPerPerson` 個持っている人には 429 を返し、`Retry-After` は付けません。アップロードが減るのは、申請がそれを持ったときか、`server.Config.UploadsKept` を過ぎてサーバーが手放したときで、待つ時間ではどちらも言えないからです。文は、いくつ持っているかと、申請に付ければ空くことを言います。

```json
{"error": "you have 50 uploaded files that no request holds yet, as many as the server keeps for one person: attach them to requests, or wait until the oldest is deleted (a file no request holds is deleted 7 days after it is uploaded)"}
```

レンダラの `FileAttachment` は、画面の `/upload` にあるアドレス（ringi の DESIGN 13.2、13.8）にファイルを送り、返った `id` を値に入れます。ハンドラーは `/upload` に `web.UploadPath`（`/files`。2.1 節）を入れます。ファイルを預からないサーバー（`server.Config.Files` が無い）では `/upload` は null のままで、`POST /files` には 404（`the server keeps no files`）を返します。ページのフォームは、ファイルをフォームと一緒に送ります。`Handler.Keep` が、それを同じやり方で本人の物として預かります（9.3 節）。

### 6.3 だれがファイルを指定でき、だれがダウンロードできるか

- **フォームでの指定。** `submit`、`resubmit`、`edit` が、型が `attachment` のフィールド（明細の行の中も）で指定するファイルは、チケットにもう載っている物か、送った本人がアップロードした物でなければなりません。ほかの ID は、無い ID も含めて 400（`form.receipt: no such file`）です。知った ID を使っても、ファイルには届きません。`Config.Files` があるとき、サーバーが `Server.Do` の中で確かめるので、API も画面もページも、ほかの入り口も同じです。
- **チケットに載る前**は、アップロードした本人だけがダウンロードできます（`/files/{id}`）。
- **チケットに載ったあと**は、そのチケットを見られる人（本体の DESIGN 10.3。差し戻しのあとの、後ろのステップの承認者も含む）が、チケットを通してダウンロードできます（`/tickets/{ticket}/files/{id}`）。ハンドラーは、チケットが持つファイルをサーバーに聞きます（`Server.TicketFiles`。本人が見られなければ 404）。チケットが持つのは、フォームが今指しているファイルと、履歴のどこかのイベント（申請、出し直し、承認者の編集）が指したファイルです。あとで差し替えた領収書も、それを指したイベントと同じく、チケットの記録に残ります。どのファイルがどのチケットに載っているかは、チケットとその動きが記録です。チケットを保存するときにほかの物を書かないので、二つが食い違うことはありません。
- **ほかの人**には 404 です。無いファイルと同じ答えです。

ダウンロードには、預かったメディアタイプ、`Content-Length`、`X-Content-Type-Options: nosniff`、ファイルの名前を入れた `Content-Disposition`（RFC 6266）を付けます。`Config.Inline` のタイプ（指定が無いときは PDF、PNG、JPEG、GIF、WebP。入れられるのもこれだけ）は `inline`、ほかは `attachment` で、CSP に `sandbox` を足します。置き場の `URL` がアドレスを返すとき（自分で中身を配る置き場）は、同じ確かめのあとで、そこへ 303 で送ります。

## 7. 設定とつなぎ方

```go
store, err := postgres.New(ctx, pool, "ringi")
srv, err := server.New(server.Config{…, Store: store, Files: store.Files(), Authenticator: web.ProxyHeader{Secret: secret}})
h, err := web.New(srv, web.Config{MaxFile: 20 << 20})
```

`Handler.Handle(pattern, handler)` は、守りの後ろにルート（`ServeMux` のパターン）を足します。ログインのルートは、これで足します（3.1 節）。

| `Server.Do` | `Config.Files` があるとき、`submit`、`resubmit`、`edit` が指定する添付を、チケットの物か本人の物に限る（6.3） |
| `server.Call.Via` | 監査ログのための入り口の印。ボタンの操作は `"screens"`、ページの送信は `"pages"` |
| `Server.Can`、`Server.Submitting` | 4 節 |
| `Server.Names`、`Server.MasterRows` | 5 節（`MasterRows` は、マスタの `MasterLayout`（キーと名前の列）と行を返す） |
| `Server.People`、`Server.Teams` | 今日有効な組織の版の人とチーム。ページの候補のため（5 節） |
| `Server.Waiting`、`server.WaitingQuery` | 本人を待っているチケット（`list_waiting`。本体の DESIGN 10.2）を新しい順に、1 ページずつ（`Kind`、`Before`、`Limit`。`Limit` が 0 なら全部）。待っている物の一覧のため |
| `Server.CountWaiting` | 本人を待っているチケットの数を、種類ごとに（`Server.Waiting` が絞らずに返すチケットを数えた物。本体の DESIGN 10.2）。ホームのため |
| `Server.Mine`、`server.MineQuery` | 本人の申請（`list_mine`。本体の DESIGN 10.4）を新しい順に、`Server.Waiting` と同じく 1 ページずつ。本人の申請の一覧とホームのため |
| `server.DefaultPage`、`server.MaxPage` | 一覧の 1 ページ。数を指定しなければ 50 件、多くて 100 件（2.1 節） |
| `Server.TicketFiles` | チケットが持つファイル（今のフォームと履歴）を、そのチケットを見られる人に |
| `Server.Upload` | アップロードを本人の物として預かり、まだどのチケットも持たない物として記録する。一人あたりの上限を超えれば `*server.TooManyUploads`（6.2 節） |
| `Server.Zone`、`Server.Now` | チケットのカードが時刻を見せる UTC オフセット。ページを見せた時刻（送信のキーがこれを読む） |
| `Server.Authenticate`、`Server.Packages`、`Server.Files`、`Server.MaxBody`、`Server.MaxOrganization` | サーバーを作ったときの物 |
| 管理の操作での `Server.Do`、`Server.AdminParts`、`Server.Administers`、`server.MaxReason` | 管理のページ（9.1 節。本体の DESIGN 13） |
| `postgres` | 表 `files (id, name, content_type, size, by_person, at, data bytea)`（2 番目の段）と `uploads`（5 番目の段。本体の DESIGN 4.2）。`(*Store).Files()` |
| `memstore.Files` | 同じインターフェースを、メモリで（`servertest.Files` は同じ型） |

## 9. 素の HTML のページ

ページは、画面を素の HTML にした物です（パッケージ `screens/page` の純粋な関数）。スクリプトを動かさないブラウザでも、申請を出し、承認し、差し戻し、自分の申請を見られます。ページのスクリプト（`page.js` と ritsu の `functions.js`）が動くときは、スクリプトでできることだけを足します。入力に合わせた計算の値、送る前の確かめ、サーバーとのやりとりなしの行の追加です。このパッケージは、ページを `/pages/` の下で出し、サーバーのデータで埋め、ページからの送信を本人として実行します。

### 9.1 各ページに出す物

| ページ | 埋める物 |
|---|---|
| ホーム | `page.Home`：本人を待っているチケットの種類と、その数（`Server.CountWaiting`。`list_waiting` が返すチケットを数えた物）。本人が出せる申請の種類（`Server.Submitting`）。本人が申請を出した種類（`Server.Mine`）。どの種類も、項目が開くページの言語（種類がその言語の画面を持てば、ページの言語）の題名で見せる。その言語のラベル、無ければ書いた題名である。ページの言語でない題名には、その言語を付ける（`Pages.TitleIn`、`Entry.Lang`） |
| 新しい申請のフォーム | 画面と同じ（2.1 節）。値の候補（5 節）、送る先のアドレス、ページを見せた時刻を足す |
| カード | 画面と同じ。値の候補、時刻を見せる UTC オフセット（`Server.Zone`）、履歴へのリンクを足す |
| チケットのフォーム | 画面と同じ。値の候補を足す |
| 履歴 | 画面と同じ。時刻を見せる UTC オフセット（`Server.Zone`。カードと同じ）を足す。例の `TestCardAndHistorySayOneTime` が、一つの承認の時刻を、両方の言語で、カードと履歴が同じに言うことを確かめる |
| 一覧 | 本人を待っているチケット（`Server.Waiting`）か本人の申請（`Server.Mine`）の `page.List`。新しい順に 1 ページ 50 件で、続きがあるときだけ次のページへのリンクを付ける（ハンドラーは、それを知るために 1 件多く読む。`?before=` はそのページの最後のチケット。2.1 節）。各行はチケットのカードへのリンクで、列は A2UI の一覧と同じ（本人の申請の一覧は、申請者の列の代わりに、代わりに申請した人（`made_by`）の列） |
| 管理のページ | 五つのうちの一つの `Pages.AdminPage`（`page.Admin.What`：使える部分、種類、組織、下書き、記録）を、管理の操作の答え（`Server.Do`、`Via: "pages"`）で埋める。それぞれが何を見せ、送ると何をするかは、本体の DESIGN 13.7 にある。人がフォームで起こしうる問題は、操作を送る前に、ページの言語で言う（`page.AdminSays`）。ホームは、`Server.Administers` がそう言うときに、これらのページへリンクする |

本人が見られないチケットのページは、API と同じく「見つかりません」の知らせ（404）です。新しい申請のフォームも、その種類に有効なバージョンが無いとき、または本人が自分の申請もだれの代わりの申請も出せないときは、その知らせです。あとのバージョンが始まる日から出せる人には、種類の題と、出せる日の一文と、ホームへのリンクのページ（これも 404。`Pages.Offered`）を見せ、ホームにはその種類を、日付つきでリンクなしに並べます。フォームとカードは、フォームが計算する物を種類の Worked の入口に聞き（`Server.Worked` を `page.WorkedFunc` として渡す）、その答えでフィールドを見せ、印を付けます。入口が失敗したらログに書き、入口が無いときと同じにページを組みます。

### 9.2 送信

フォームは、そのフォームを出したページに送ります。ハンドラーは、ページを作ったときと同じ入力を今の時点で作り直して、送信を読みます（`page.ReadForm`、`page.ReadCard`）。押したボタン、入れた値、足したり消したりした行、選んだファイルです。文、長い文、コメントは、両端の空白を除いて読みます（Unicode の `White_Space` の 25 字。ページの DESIGN 4.1）。読んだ結果は次のどれかです。

- **スクリプトなしのページで、フィールドで Enter を押した**（フォームの最初の、だれにも見えないボタン。`page.DoStay`）：204 No Content を返し（`Reading.Stay`）、ブラウザはページをそのまま残します。入れた値、選んだファイル、フォーカスの位置もそのままです。送信の中身は読まず、ファイルも預かりません。
- **行を足したか消した**（スクリプトなしで見せたページのボタン）：入れた値のままページを見せ直します。200 です。
- **ページの確かめで止まった**（読めない値、種類の関数がする確かめ、必須の値が無い）：入れた値のまま、問題をそれぞれのフィールドとフォームの頭に書いて、ページを見せ直します。422 です。
- **チケットが変わる前に見せたページだった**：ページは別のリビジョンのチケットを見せていて、押したボタンは、今のゲートが本人に許す物ではありません。操作は送らず、今のチケットでページを見せ直し、`stale` の断りを付けます。409 です（コメントはリビジョンが要らないので、これに当たりません）。
- **操作**：本人として実行します（`Server.Do`。`Via: "pages"`）。

操作の答えは次のとおりです。

- **受け付けた**：チケットのカード（新しい申請なら、新しいチケットのカード）への 303 です。ブラウザはカードを GET で開くので、ページを送り直しても、二度目の操作にはなりません。
- **断られた**（409）：入れた値のままページを見せ直し、断りを言います（`Reading.Refused`）。ページの頭には、断りの種類から作った一文（2.2 節）を書き、その下に API の文をページの言語で添えます。`form` の断りは、指す場所（`at`）の部品にも書きます。フィールド、明細の行のフィールド、明細の行でフォームが計算するセル（`lines[0].subtotal`）のどれかで、計算するセルの断りは、その行のセルの横に、セルの範囲の言葉で書きます。`comment` の断りは、どの操作でも、コメントの下に書きます。`stale`、`state`、`person` のあとは、チケットを読み直し、押せるボタンだけの今のチケットで見せます。本人がもう見られないときは「見つかりません」の知らせです。
- **invalid**（400）：API と同じ問題の文を付けて、ページを見せ直します。
- **limited**（429）：サーバーがいまは受け付けないコメントです。入れた値のままページを見せ直し、頭にそのことを書きます（`screens.LimitedWords`）。待てば受け付けるときは `Retry-After` を付けます。
- **見つからない**：「見つかりません」の知らせ（404）です。

ページのスクリプトは、フォームを送ったら、答えが来るまで送り直させません。送ってから 3 秒たてば、また送れるようにします。本人が止めた送信には、答えが来ないからです。同じページから同じ値で送り直した操作は同じキーを持つので、サーバーは一度目と同じに答えます。新しい申請なら、同じチケットです。

送り先のページの物でない送信（どのボタンも押していない、別のページのサーフェス、読めないリビジョンや時刻）は、「送った内容を読めませんでした」の知らせ（400）です。

### 9.3 送信の中のファイル

添付のフィールドを持つフォームは `multipart/form-data`、ほかは `application/x-www-form-urlencoded` です（ほかのタイプは 415）。本文の上限は、サーバーの `MaxBody` と、10 個までのファイルそれぞれの `Config.MaxFile` で、超えれば 413 です。選んだファイルは、操作を作る前に、本人のアップロードとして預かり（`Handler.Keep`。確かめは 6.2 と同じ）、フォームはその ID で指します。一つのフィールドが読むファイルは、送信がその名前でいくつ送っても一つです。大きすぎるファイル、受け付けないタイプのファイル、申請に付いていないアップロードが一人あたりの上限に達したあとのファイルは、そのフィールドに理由を書いて（`page.FileRefusal`）、ページを見せ直します。そのフィールドが前に持っていたファイルは残ります。受け付けなかった送信（ページの確かめで止まったか、サーバーが断った）でも、預かったファイルは本人のアップロードとして残り、見せ直したページがそれを持つので、選び直さずに済みます。申請がそのファイルを持つのは、受け付けた送信で付けたときだけです。どの申請も持たないアップロードは、サーバーがあとで手放します（本体の DESIGN 2.3）。送信の一時ファイルは、リクエストが終われば消えます。

### 9.4 言語

ページは一つの言語で見せます。`?lang=` で選んだ言語（それからはクッキー `ringi-lang` が覚える。`HttpOnly`、`SameSite=Lax`、TLS なら `Secure`、一年）、無ければクッキーの言語、無ければ `Accept-Language` のうち、そのページを見せられる最初の言語、無ければ組織のデータがログインしている人に与える言語（`Server.PersonLanguage`。ヘッダーが `q=0` で断っていなければ）、無ければ種類の説明を書いた言語、それも無ければ英語です。ページ、画面、管理のページ、ログインのページは、一つの関数で選びます（`server.LanguageChoice`）。ログインの前のページには、人の言語はありません。種類のページは、その種類の言語を選べます。ホームと知らせは、英語と日本語です。ページ自身の言葉は英語と日本語で、どちらでも書かれていない種類は、種類の言葉はその言語で、ページの言葉は英語で見せます。ページのリンクは、開いたときの `?lang=` を引き継ぎます。ログインのページ（パッケージ `oidc`）も同じクッキーを読み、ページで選んだ言語で話します。

`Accept-Language` は `server.AcceptLanguages` で読みます。`q` の大きい順で、同じ `q` はヘッダーの順、`q=0` の言語は望まないと読みます（`en;q=0.1, ja` は日本語を先に望み、`ja;q=0` は日本語を望みません）。MCP のツール、ログインのページ、パッケージ `devlogin` の試用のログインも同じ関数で読み、一つのヘッダーがどれでも同じ言語を選びます。

### 9.5 帯と知らせ

どのページも、上に帯を持ちます（`page.Bar`。ハンドラーがページの `Bar` に入れ、画面の `<main>` の前に置く）。ホームへのリンク、ログインしている人の名前（ページの言語で）、ほかの言語のページへのリンク、ログアウトのボタン（`Config.SignOut`）です。

知らせは、求められたページの代わりに見せるページです（`page.Notice`）。帯を付け、ページの言語で見せます。

| 知らせ | ステータス | とき |
|---|---|---|
| 見つかりません | 404 | 無いページ、または本人が見られないチケット |
| ログインしていません | 401 | 人のいないページの要求。リンクでログインする（`Config.LoginURL`） |
| 送った内容を読めませんでした | 400、403、415 | 読めない送信、どのページの物でもない送信、別のサイトから送られた送信 |
| 送った内容が大きすぎます | 413 | 9.3 節の上限を超えた |
| サーバーのエラー | 500 | サーバーの失敗。ログに書く |

### 9.6 ページが使う物

ページと A2UI の画面は、このパッケージのほかの物を一緒に使います。だれが送ったか（`Server.Authenticate`。ページはさらに `Config.Require`）、守り（3 節）、名前のための `Handler.Lookup`、選ぶ部品が値を探すアドレス（`/find`、`web.FindPath`。5.1）、ボタンと代わりに出せる人のための `Server.Can` と `Server.Submitting`、ファイルのための `Handler.Keep`、リンクのためのダウンロードのルート、断りのためのパッケージ `screens` の文です。
